## 任務卡

### T-10 在學習影音、廣場活動、個人視訊裡左右大滑切換膠囊分頁

**使用者價值**：使用者在學習→影音→文章、動態↔活動、個人資料↔視訊配對之間，不必把手指伸到頂部膠囊，在內容上往左／右大滑一次就換到隔壁那塊；輕輕帶過或斜著捲清單不會誤切。

**範圍**
- 包含：三個膠囊宿主（學習影音三段、廣場活動兩段、個人視訊兩段）內容區的左右滑切換；膠囊選中狀態跟著變。
- 不包含：底部導航五個分頁之間的滑動切換；從分頁推進去的詳情頁、其他畫面裡的 `TabBarView`（收件匣、我的收藏等，本來就能滑）。

**驗收條件**
- [x] 手指往左滑切到右邊一段、往右滑切到左邊一段；學習影音可連續 學習→影音→文章，反向亦然。在第一段往右、最後一段往左滑不動作，也不繞回另一端。
- [x] 水平滑動距離超過螢幕寬約四成才切換；不到就放開不切，快速輕甩（距離短、速度快）也不切。門檻實機調。
- [x] 斜向或以上下為主的滑動照常捲清單，不會觸發切換。
- [ ] 在本身能橫滑的元件上（影音精選輪播、分類 chip 列、論壇看板列、活動封面橫列、活動篩選 chip、搜尋列 chip）滑動，動的是那個元件，不切分頁。
- [ ] 滑動切換的結果與點膠囊完全相同：頂部底色、各段捲動位置、文章分類與排序都和點擊切換時一樣。
- [ ] 滑動中內容跟手微幅位移（最多約 24px）並略為淡化（最低約 0.85），不到門檻放開時平滑彈回，換段時新內容從正常位置與不透明度出現；捲動、點擊不受影響。
- [x] 頂部膠囊的選中色塊跟著手指往隔壁段移；滑到門檻時色塊剛好到位，不到門檻放開時色塊彈回原段；在兩端往外滑色塊不動。
- [ ] 一般與精簡模式行為相同；Web 用滑鼠拖曳不觸發（只認觸控）。

**實作設計**
- 前端（共用元件）：新增 `lib/shared/widgets/swipe_segment_switcher.dart` 的 `SwipeSegmentSwitcher`，介面：`index`、`count`、`onChanged(int)`、`child`，選填 `distanceFraction`（預設約 0.4）。內部用 `GestureDetector` 的 `onHorizontalDragStart/Update/End` 累計 `dx`、`dy`，放開時 `|dx| ≥ 寬 × distanceFraction` 且 `|dx| > 2|dy|` 才呼叫 `onChanged(index ± 1)`，超出 0..count-1 時不呼叫；不看 fling 速度。`supportedDevices` 限觸控與觸控筆。內層橫向捲動元件在手勢競技場裡較深、會先贏，所以不必另外排除。
- 前端（宿主）：`LearnCultureScreen` 把 `Expanded` 裡的 `IndexedStack` 包一層 `SwipeSegmentSwitcher(count: 3, onChanged: 同膠囊)`；`PlazaEventScreen`、`ProfileVideoScreen` 包住 `Scaffold.body` 的 `IndexedStack`（`count: 2`）。三處 `onChanged` 都走跟膠囊同一個 `setState(() => _tabIndex = i)`，抽成私有 `_select(int)` 共用。
- 前端（內容特效）：`SwipeSegmentSwitcher` 內部把 `child` 包 `Transform.translate(dx: progress × 24)`＋`Opacity(1 - |progress| × 0.15)`（`progress` 與 `onDragProgress` 同一個值，兩端往外滑時同樣夾成 0）；放開時用 `AnimationController` 約 200ms 把 progress 歸 0，換段的那次直接歸 0 不做動畫，避免新內容從偏移處滑回來。位移露出的邊緣是宿主 `Scaffold` 底色（學習紅／影音深色／米白），與內容底色相同時不明顯。
- 前端（膠囊回饋，已拍板 B）：膠囊選中色塊跟著手指往隔壁段預移，放開才真的換內容。`SwipeSegmentSwitcher` 多一個 `onDragProgress(double)`（-1..1，相對門檻的比例，放開或取消時歸 0）；`PillSegmentedToggle` 加選填 `dragProgress`（預設 0，原有呼叫端不受影響），選中色塊改成一個獨立的 `AnimatedPositioned`／`Align` 疊在各段下方，位置 = `index + dragProgress`，到門檻時剛好蓋住隔壁段；文字顏色仍依 `index` 決定，放開後才變。在兩端往外滑時 `dragProgress` 夾成 0，不往外移。宿主把 `dragProgress` 存在 state 傳給膠囊。
- 測試：`test/` 加 widget test，驗證短距離、快速輕甩、縱向為主的拖曳不切，超過門檻切到隔壁段、兩端不越界。

**依賴**：無

**風險 / 待決**：廣場活動與個人視訊的膠囊會跟著內容捲走，捲下去之後滑動時看不到色塊回饋，只剩內容微移（已接受）。內層橫向清單滑到盡頭時，多出來的拖曳不會轉交給外層切換（使用者得從清單以外的地方滑）；Android 手勢導航的左右邊緣滑動由系統攔做返回，不會進到 App，實機確認兩者不互搶。

**進度**：實作完成（2026-10-02）
- commit：8e32727..768c752（分支 feat/pill-swipe-switch）
- 決定：搶手勢改用自訂 `HorizontalDragGestureRecognizer` 子類，水平位移大於垂直兩倍才搶下手勢，不用 `GestureDetector` 的 `onHorizontalDrag*`。原因是一般水平拖曳只要水平分量先過 slop 就搶，27°～45° 的斜滑會被搶走、放開時又不夠水平而不切，清單也不捲。
- 決定：滑動進度經 `ValueNotifier` 只重建膠囊，不經宿主 `setState`，避免每一幀重建整頁內容。
- 未驗：實機調門檻手感；在實際的影音精選輪播、分類 chip、論壇看板列、活動封面橫列、活動篩選 chip、搜尋列 chip 上滑動不切（測試只用一般橫向清單模擬）；滑動與點擊切換後頂部底色、捲動位置、文章分類排序一致；內容微移淡化與彈回的視覺、中低階 Android 上 `Opacity` 是否掉幀；精簡模式行為；Android 手勢導航邊緣返回不互搶。
