## 現況與前提
- 技術棧：Flutter，所有請求走 `ApiClient`（`lib/core/network/api_client.dart`），錯誤統一丟 `ApiException`。
- 既有相關機制：
  - `FcmService._parseReminderPayload`（`lib/services/fcm_service.dart`）只認 `event_reminder`／`event_cancelled`；前景時以本機通知＋SnackBar「查看」呈現，本機通知 payload 只放 eventId 字串，點擊一律走 `onReminderTapped` → `openEventPush`（`lib/screens/content_push_navigation.dart`）開活動詳情。`event_deleted` 目前被忽略。
  - 活動詳情頁以 `FcmService.onReminderReceivedForOpenScreen` 在前景收到本活動推播時重抓提醒。
  - 刪除活動：`EventService.deleteEvent` 回 `void`；`event_detail_screen.dart` 的 `_deleteEvent` 成功後 `Navigator.pop(context, true)` 通知列表刷新。
  - 發提醒：`ReminderComposeScreen`（由 `event_action_bar.dart` 帶 `eventId`、`eventTitle` 開啟）已把 `ApiException.message` 用 SnackBar 顯示，`REMINDER_LIMIT`／`INVALID_REMINDER_TIME` 的訊息不用另外處理；日期選擇上限寫死「現在＋365 天」，畫面拿不到活動結束時間。`EventDetail.endsAt` 可為 null（舊資料）。
  - 影片播放：`video_detail_screen.dart` 以固定 16:9 的 `AspectRatio` 包住播放器，`BetterPlayerConfiguration` 也是 16:9＋`BoxFit.contain`；影片 API 沒有寬高欄位。
- 這次會動到的既有部位：`lib/services/fcm_service.dart`、`lib/services/event_service.dart`、`lib/main.dart`；`lib/screens/events/` 的 event_detail_screen、joined_events_screen、reminder_compose_screen、widgets/event_action_bar；`lib/screens/culture/video_detail_screen.dart`。
- 已定案的技術前提：

  - 直拍影片的播放框依影片實際比例顯示。

## 任務卡

### T-01 報名者收到「活動已被刪除」通知時知道發生什麼事，不會開到找不到的頁面

**使用者價值**：報名的活動被發起人刪除時，報名者會被告知，而不是點通知後看到「找不到活動」。

**範圍**
- 包含：`event_deleted` 的前景、背景、冷啟動處理；「我參加的活動」即時刷新；正在看該活動詳情時的處理。

**驗收條件**
- [ ] 前景收到時跳出本機通知與 SnackBar，顯示推播內文（「您參加的{活動名稱}已被發起人刪除」），SnackBar 不帶「查看」。
- [x] 前景收到時若「我參加的活動」頁開著，列表自動重新整理，該活動消失。
- [x] 前景收到時若正在看該活動詳情頁，跳出對話框說明活動已被發起人刪除，按確定後關閉詳情頁。
- [ ] 背景或冷啟動點通知：App 停在首頁，並跳出提示說明哪個活動已被發起人刪除；不開活動詳情頁。
- [ ] `event_reminder`／`event_cancelled` 行為不變。

**實作設計**
- 前端：
  - `fcm_service.dart` 新增 `_parseEventDeleted`（`type == 'event_deleted'`，取 `event_id` 與通知 title／body），前景、背景點擊（`onMessageOpenedApp`／`getInitialMessage`）、本機通知點擊三條路徑都要接。
  - 本機通知 payload 用 `event_deleted:` 前綴（比照 `video:`、`forum:`），並帶上內文供點擊後顯示。
  - 新增 `FcmService.onEventDeleted`（前景：通知開著的畫面）與 `onEventDeletedTapped`（點擊：顯示提示）兩個回呼：
    - `main.dart` 設定 `onEventDeletedTapped`，以 `scaffoldMessengerKey` 或全域 navigator 顯示提示，不導頁。
    - `joined_events_screen.dart` 與 `event_detail_screen.dart` 在 init 登記、dispose 解除（比照 `onReminderReceivedForOpenScreen` 的登記方式）；詳情頁只在 `eventId` 相同時反應。
- 測試：`_parseEventDeleted` 單元測試，payload 依規格手寫。

**依賴**：無

**風險 / 待決**：多個畫面同時登記同一個回呼時會互相覆蓋，參考既有 `onReminderReceivedForOpenScreen` 的比對解除寫法，或改成監聽者清單，由實作者判斷。

**進度**：實作完成（2026-09-29）
- commit：af4d691
- 未驗：真實 FCM 推播的本機通知；背景與冷啟動點通知只在首頁跳提示（回呼有單元測試，導覽需實機）；`event_reminder`／`event_cancelled` 實際行為（僅 parse 層與既有測試）。已知限制：停在該活動詳情頁時 App 進背景，再點通知回來只會跳提示，詳情頁不會自動關閉。

### T-02 發起人刪除活動後知道通知了幾位報名者

**使用者價值**：發起人刪除活動時能確認報名者已經收到通知，不必另外聯絡。

**範圍**
- 包含：讀 `DELETE /api/events/:id` 回應的 `notified`，刪除成功後顯示。

**驗收條件**
- [x] 刪除成功且 `notified > 0` 時顯示「活動已刪除，已通知 N 位報名者」。
- [x] `notified` 為 0 或缺少時只顯示「活動已刪除」。
- [x] 刪除失敗行為不變。

**實作設計**
- 前端：`EventService.deleteEvent` 改回 `int`（`notified`，缺少當 0）；`_deleteEvent` 成功後以 `scaffoldMessengerKey`（詳情頁即將 pop）顯示 SnackBar，再 `Navigator.pop(context, true)`。
- 測試：回應依規格手寫（inspector 錄製會真的刪活動）。

**依賴**：無

**進度**：實作完成（2026-09-29）
- commit：83258a7
- 未驗：`notified` 欄位依規格手寫，未對真實後端驗證（錄製會真的刪活動）。

### T-03 發起人排提醒時只能選到活動結束前

**使用者價值**：發起人不會排出活動結束後才送出的提醒，也在超過每日上限時看到原因。

**範圍**
- 包含：提醒畫面的時間上限與送出前檢查、兩個新錯誤碼的顯示確認。

**驗收條件**
- [x] 日期選擇器的最後一天是活動結束日（活動沒有結束時間時維持現在＋365 天）。
- [x] 選到結束日當天但時間晚於結束時間時，顯示「發送時間不能晚於活動結束（{結束時間}）」，不接受該時間。
- [x] 送出前再檢查一次同樣條件。
- [ ] 同一天已有 3 則提醒時，SnackBar 顯示後端 `REMINDER_LIMIT` 的 `message`。
- [ ] 後端回 `INVALID_REMINDER_TIME` 時 SnackBar 顯示其 `message`。

**實作設計**
- 前端：`ReminderComposeScreen` 加選填參數 `eventEndsAt`（`DateTime?`），`event_action_bar.dart` 開啟時傳 `e.endsAt`；`_pickDateTime` 的 `lastDate` 取 `min(endsAt, now + 365 天)`，選完時間後比對；`_submit` 加同樣檢查。

**依賴**：無

**進度**：實作完成（2026-09-29）
- commit：ded6b64
- 未驗：`REMINDER_LIMIT`、`INVALID_REMINDER_TIME` 顯示後端 `message`（沿用既有 `ApiException` 處理，讀 code 確認，未另寫測試）；活動實際結束時間與時區的實機顯示。

### T-04 直拍影片以原本的直式比例播放

**使用者價值**：手機直拍的影片不再縮在 16:9 框中間的一小條，看得清楚。

**範圍**
- 包含：HLS 播放器的播放框依影片實際比例。
- 不包含：YouTube 影片（維持 16:9）；列表縮圖（後端固定 480×270）。

**驗收條件**
- [ ] 直拍影片載入後播放框變成直式比例，畫面不被拉伸、不被裁切。
- [ ] 直式影片的播放框高度有上限，下方標題與說明仍能在首屏看到開頭（上限數值由實作者依實機調整）。
- [ ] 橫式影片顯示與現在相同。
- [ ] 影片尚未載入完成前以 16:9 佔位，載入後切換比例不閃爍跳動過大。
- [ ] 全螢幕播放時直式影片正確顯示。

**實作設計**
- 前端：`video_detail_screen.dart` 在 `BetterPlayerController` 初始化完成後讀取 `videoPlayerController.value.aspectRatio`，存成 state；`_buildContent` 的 `AspectRatio` 改用該值，並以 `ConstrainedBox` 限制最大高度；`BetterPlayerConfiguration` 的 `aspectRatio` 同步設定（或改用 `autoDetectFullscreenAspectRatio`，待確認套件支援）。

**依賴**：無

**風險 / 待決**：需要一支直拍的測試影片，後端轉檔改善後重新上傳的才會是直式。

**進度**：實作完成（2026-09-29）

- 未驗：需實機——直式影片載入後比例、首屏標題可見的上限（目前螢幕高 55%，且只限制直式）、橫式影片與現在相同、載入後切換比例的跳動程度、全螢幕直式顯示與方向、影片旋轉 metadata 對比例的影響。版面計算有 widget 測試。
