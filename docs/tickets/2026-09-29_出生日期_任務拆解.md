# 2026-09-29 出生日期與隨機配對年齡限制 任務拆解

來源：`Truku_backend` 分支 `feat/pol01-birth-date` 上的 `說明文件/前端交接/2026-09-27_前端待辦.md` I 段（POL-01，決策紀錄 A23）。規格：同分支 `API/00_核心與認證.md` §2.1、§2.3、§2.4a、§2.4c，`API/用戶視訊.md`。後端尚未合併、尚未部署。管理員更正出生日期（`內部管理.md` §8.3a）在 `2026-09-29_管理員後台_任務拆解.md` T-16。

## 現況與前提
- 技術棧：Flutter，所有請求走 `ApiClient`，錯誤統一丟 `ApiException`（`is*` getter 集中在 `lib/core/network/api_client.dart`）。
- 既有相關機制：
  - 登入後導頁由四處各自判斷：`splash_screen.dart`、`login_screen.dart`、`terms_consent_screen.dart`、`account_pending_screen.dart`，都讀 `UserModel.profileCompleted` 決定 `/complete-profile` 或 `/home`（splash、login 另外判斷 `/terms-consent`）。路由表在 `main.dart`。
  - `CompleteProfileScreen`（`lib/screens/auth/complete_profile_screen.dart`）送 `UserService.completeProfile`，欄位有暱稱、公開暱稱、是否原住民、族別、部落。
  - 隨機配對入口是 `community_screen.dart` 的「開始配對」按鈕（`_startMatching`），`ApiException` 中 `VIDEO_NICKNAME_REQUIRED` 開對話框、其餘顯示 message；等待畫面 `video_waiting_screen.dart` 重新排隊遇到 403 由 `_stopForbidden` 停止並顯示訊息。
  - 個人資料頁 `profile_info_screen.dart` 以列表顯示自我介紹、好友碼等欄位。
  - main 上的後端 `POST /api/me/complete-profile` 只解構認得的欄位，多送 `birth_date` 會被忽略，新版 App 接舊後端不會出錯。
- 這次會動到的既有部位：`lib/models/user_model.dart`、`lib/services/user_service.dart`、`lib/core/constants/api.dart`、`lib/core/network/api_client.dart`、`lib/main.dart`；`lib/screens/auth/`（complete_profile_screen、login_screen，新增補填頁）、`lib/screens/splash/splash_screen.dart`、`lib/screens/terms/terms_consent_screen.dart`、`lib/screens/account/account_pending_screen.dart`、`lib/screens/community/`（community_screen、video_waiting_screen）、`lib/screens/profile/profile_info_screen.dart`；`test/fixtures/api/`。
- 已定案的技術前提：
  - 出生日期 `YYYY-MM-DD`，必填、不公開、使用者只能填一次，不可自行修改；日期須實際存在、不晚於今天（台灣時間）、不早於 120 年前。
  - 未滿 18 歲（台灣時間日期計算，生日當天算滿）不得使用隨機配對；好友定向通話不受影響。
  - 上線順序：**App 先上架，後端之後再上線**（使用者決定，取代後端交接的「同時上線」）。App 必須在舊後端（沒有 `birth_date`、`needs_birth_date`）下行為與現在相同。
  - 未滿 18 歲時「開始配對」按鈕變暗，前端依 `birth_date` 自行計算年齡。
  - 新版條款（I5）由後端上線當天發布，沿用既有同意流程，不開卡。
- 已知限制：
  - 後端未部署前錄不到新欄位與 `POST /api/me/birth-date`，fixture 依規格手寫；後端上線後以 inspector 補錄 `GET /api/me` 並核對。
  - App 先上、後端未上線的空窗期註冊的人，填的生日不會被存下來，後端上線後 `needs_birth_date=true`，會被 T-02 要求再填一次。
- 收尾（不開卡）：App 上架 → 通知後端合併部署 POL-01 並發布新版條款 → 把 Remote Config 最低版本提高到此版（後端上線後舊版 App 無法完成註冊）。

## 任務卡

### T-01 新使用者填基本資料時必填出生日期

**使用者價值**：新使用者註冊時就留下出生日期，App 才能判斷能不能使用隨機配對。

**範圍**
- 包含：`UserModel` 新欄位、基本資料頁的出生日期欄位、送出時帶 `birth_date`。
- 不包含：舊使用者補填（T-02）、年齡限制（T-03）。

**驗收條件**
- [x] 基本資料頁多一個必填的「出生日期」，點選開日期選擇器，不能選未來日期、不能早於 120 年前；未填時無法送出並提示。
- [x] 欄位下方註明「用來確認是否年滿 18 歲，不會公開；填寫後無法自行修改」。
- [x] 送出 `POST /api/me/complete-profile` 帶 `birth_date`（`YYYY-MM-DD`，以使用者選的日期為準，不受時區換算影響）。
- [x] 後端回 `400 INVALID_REQUEST` 時顯示 `message`。
- [ ] 接目前正式後端（未上 POL-01）註冊流程照常完成。
- [ ] 精簡模式字級與間距正確。

**實作設計**
- 前端：
  - `UserModel` 加 `birthDate`（`DateTime?`，只取日期）與 `needsBirthDate`（缺少當 `false`），`toJson`／`copyWith` 同步。
  - `UserService.completeProfile` 加必填參數 `birthDate`，格式化為 `YYYY-MM-DD`。
  - `complete_profile_screen.dart` 加日期欄位（共用元件 `BirthDateField`，T-02 補填頁與後台 T-16 重用），`showDatePicker` 的 `firstDate`＝今天往前 120 年、`lastDate`＝今天。
- 測試：`get_api_me.json` 依規格手寫補上 `birth_date`、`needs_birth_date` 的版本，補契約測試；後端上線後以 inspector 補錄核對。

**依賴**：無

**進度**：實作完成（2026-09-29）
- commit：3160482、56af597
- 未驗：接目前正式後端完成註冊、精簡模式字級與間距（需實機）

### T-02 舊使用者被擋下補填出生日期才能進 App

**使用者價值**：出生日期上線前就註冊的人，補填一次後就能正常使用，年齡限制才對所有人生效。

**範圍**
- 包含：導頁判斷收斂、補填頁、`409` 處理、隨機配對遇到 `BIRTH_DATE_REQUIRED` 時導去補填頁。

**驗收條件**
- [x] 冷啟動、登入、同意條款後、帳號重新啟用後，`profile_completed=true` 且 `needs_birth_date=true` 時都導到補填頁，不能返回、不能跳過。
- [x] 補填頁說明文字同 T-01，送出 `POST /api/me/birth-date` 成功後進首頁（或條款頁，依既有順序）。
- [x] `409 BIRTH_DATE_ALREADY_SET` 時重抓 `/api/me` 並直接放行。
- [x] `400 INVALID_REQUEST` 顯示 `message`。
- [x] 補填頁提供登出，讓使用者能換帳號。
- [x] 舊後端（沒有 `needs_birth_date`）下導頁行為與現在相同。

**實作設計**
- 前端：
  - 新增 `lib/screens/auth/entry_route.dart` 的 `entryRouteFor(UserModel user, {required bool allConsented})`，回 `/complete-profile`、`/birth-date`、`/terms-consent` 或 `/home`；四處導頁改呼叫它，順序沿用既有邏輯（未完成基本資料優先，其次補填生日，再其次條款）。
  - 新增 `lib/screens/auth/birth_date_screen.dart`，`PopScope(canPop: false)`；`main.dart` 路由表加 `/birth-date`。
  - `ApiConfig` 加 `meBirthDate = '/api/me/birth-date'`；`UserService.submitBirthDate(DateTime)` 回完整 user 並更新快取。
  - `ApiException` 加 `isBirthDateRequired`、`isBirthDateAlreadySet`。
- 測試：`entryRouteFor` 單元測試涵蓋各組合；補填 API 回應依規格手寫。

**依賴**：T-01（`UserModel` 欄位、`BirthDateField`）

**風險 / 待決**：冷啟動由通知帶出的深連結（`FcmService.consumePendingInitialMessage`）要在補填完成後才執行，比照條款頁的處理方式。

**進度**：實作完成（2026-09-29）
- commit：afc0737、28e3bd3
- 未驗：後端 POL-01 上線後以實際 `needs_birth_date=true` 帳號走一次補填（需實機）

### T-03 未滿 18 歲的人看到隨機配對不能用，並被引導去跟好友視訊

**使用者價值**：未成年使用者不會與陌生成人一對一視訊，且知道還能跟好友視訊。

**範圍**
- 包含：「開始配對」按鈕依年齡變暗、`403 UNDERAGE`／`BIRTH_DATE_REQUIRED` 處理（入口與等待畫面）。
- 不包含：好友定向通話（不受影響）。

**驗收條件**
- [x] 依 `/api/me` 的 `birth_date` 以台灣時間計算，未滿 18 歲時「開始配對」按鈕變暗、不會開始配對；生日當天算滿 18 歲。
- [x] 點變暗的按鈕顯示「未滿 18 歲無法使用隨機配對，可以與好友視訊」，並提供前往好友列表。
- [x] 沒有 `birth_date`（舊後端或尚未補填）時按鈕照常可點，由後端判斷。
- [ ] 按鈕可點但後端回 `403 UNDERAGE` 時，顯示同樣說明與前往好友列表；回 `403 BIRTH_DATE_REQUIRED` 時導去補填頁。
- [ ] 等待畫面重新排隊收到這兩個錯誤時停止輪詢、離開等待畫面，並依上一條處理。
- [x] 管理員更正生日後（重抓 `/api/me`），按鈕狀態跟著變。

**實作設計**
- 前端：
  - `UserModel` 加 `bool? get isAdult`：`birthDate` 為 null 回 null；否則以台灣時間（UTC+8）的今天日期比較年月日。
  - `community_screen.dart` 以 `ValueListenableBuilder` 監聽 `UserService.userNotifier`，`isAdult == false` 時按鈕改暗色、`onTap` 改為顯示說明底板（含「前往好友列表」）。
  - `_startMatching` 與 `video_waiting_screen.dart` 的 `_stopForbidden` 依 `isUnderage`／`isBirthDateRequired` 分流；`ApiException` 加 `isUnderage`。
- 測試：`isAdult` 單元測試（生日前一天、當天、跨年、閏年 2/29）。

**依賴**：T-01（`UserModel.birthDate`）

**進度**：實作完成（2026-09-29）
- commit：5420553
- 未驗：「開始配對」與等待畫面收到 `403 UNDERAGE`／`BIRTH_DATE_REQUIRED` 後在入口顯示說明或導去補填頁——處理函式與等待畫面帶回錯誤有測試，入口接線要權限與相機，需實機
