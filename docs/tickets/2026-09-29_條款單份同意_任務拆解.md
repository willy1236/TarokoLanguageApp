## 現況與前提
- 技術棧：Flutter，所有請求走 `ApiClient`（`lib/core/network/api_client.dart`），錯誤統一丟 `ApiException`。
- 既有相關機制：
  - `terms_consent_screen.dart` 以 `GET /api/terms` 一次取回兩份，TabBar 分頁顯示；每份捲到底才解鎖勾選，全部勾完後「同意並繼續」一次送 `POST /api/terms/consent`（body `{ versions }`）。409 `TERMS_VERSION_OUTDATED` 由 `_reloadOutdated` 換成回應附的最新版。
  - 同一畫面也是唯讀模式（`readOnly: true`，個人頁點進來）。
  - splash、login 以 `TermsService.fetchStatus()`（`GET /api/terms`）取 `all_consented` 判斷是否導去同意畫面。
  - `ApiClient._throwError` 收到 403 `CONSENT_REQUIRED` 時導去同意畫面，只排除寫死的 `/api/terms`、`/api/terms/consent`，單份路徑不在排除內。
- 這次會動到的既有部位：`lib/core/constants/api.dart`、`lib/services/terms_service.dart`、`lib/models/terms_models.dart`、`lib/screens/terms/terms_consent_screen.dart`、`lib/core/network/api_client.dart`；`test/widgets/terms_consent_screen_test.dart`。
- 已定案的技術前提：
  - 只換同意畫面；splash、login 的同意檢查維持 `GET /api/terms`。
  - 強制同意改成逐份處理：一次一份，同意當下就送出該份。
  - 只顯示尚未同意最新版的那幾份；沒改版的那份不出現，要看從個人頁唯讀模式進去。

## 任務卡

### T-01 使用者逐份閱讀並同意服務條款與隱私權政策

**使用者價值**：每份條款各自留下同意紀錄；條款改版時只需重新同意改到的那份。

**範圍**
- 包含：強制同意模式改成逐步流程，讀取與送出改用單份端點；唯讀模式讀取也改用單份端點。
- 不包含：splash、login 的同意檢查（維持合併版）。

**驗收條件**
- [x] 強制同意時一次只顯示一份，順序為服務條款 → 隱私權政策，並顯示「第幾份／共幾份」（總數為尚未同意的份數，可能是 1）。
- [x] 捲到底才解鎖「同意《服務條款》」按鈕；按下後立即送出該份同意，成功才進到下一份。
- [x] 最後一份同意成功且回應 `all_consented` 為 true 時，照現有邏輯進首頁或完善資料頁。
- [x] 送出單份時回 409 `TERMS_VERSION_OUTDATED`：換成回應附的最新版內容，停在該份，需重新捲到底。
- [x] 只有一份改版、或前一份已同意後中途離開再回來時，已同意最新版的那份不出現。
- [x] 某種條款尚未發布（`404 TERMS_NOT_FOUND`）時略過該份，不當錯誤。
- [x] 唯讀模式和現在一樣以分頁顯示兩份，不可同意、可返回。
- [x] 同意畫面送出時被回 403 `CONSENT_REQUIRED` 不會觸發導去同意畫面的迴圈。

**實作設計**
- 前端：
  - `api.dart` 新增 `termsDoc(docType)`、`termsDocConsent(docType)`。
  - `TermsService` 新增 `fetchDocument(docType)`（回 `{ document, all_consented }`）與 `consentDocument(doc)`（body `{ version }`）。
  - `terms_models.dart` 新增單份回應 model，重用 `TermsDocument`。
  - `terms_consent_screen.dart`：以 `Future.wait` 並行抓 tos、privacy；強制模式只留 `consented == false` 的文件，改成步驟索引切換的單頁，移除分頁、勾選框與「尚餘 N 份」；唯讀模式保留分頁。409 沿用 `_reloadOutdated`（回應為合併版形狀），挑出目前這份。
  - `api_client.dart` 排除條件改成 `path == '/api/terms' || path.startsWith('/api/terms/')`。
- 測試：
  - 依 API 優先慣例，先用 integration test 錄 `GET /api/terms/tos`、`GET /api/terms/privacy` fixture（需人點 Google 帳號，集中一次錄、先提醒）。
  - POST 同意會真的寫紀錄，回應依規格手寫。
  - 更新 `terms_consent_screen_test.dart`，補逐步流程、409、只剩一份的情境。

**依賴**：無

**風險 / 待決**：步驟之間要不要加換頁動畫，由實作者判斷。

**進度**：實作完成。驗收條件已由 widget test 驗證（718 項全綠、analyze 無問題），獨立審查（Opus 5.5）發現的閱讀進度殘留、mounted 檢查已修。尚待：錄 `GET /api/terms/tos`、`/privacy` 單份 fixture（需人點 Google 帳號，與其他 fixture 集中一次錄）；實機驗證逐步流程與捲到底解鎖。
