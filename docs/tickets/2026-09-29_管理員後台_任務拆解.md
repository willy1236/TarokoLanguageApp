## 現況與前提
- 技術棧：Flutter，所有請求走 `ApiClient`（`lib/core/network/api_client.dart`），錯誤統一丟 `ApiException`（`code`、`message`、`body`）。
- 既有相關機制：
  - App 內沒有任何後台畫面。`UserModel.role`（`user`／`organizer`／`admin`）已解析，`canCreateEvent` 以 role 判斷；`UserService.userNotifier`（`ValueNotifier<UserModel?>`）是目前登入者的快取，`fetchMe(forceRefresh: true)` 重抓。
  - `events_screen.dart` 在 init 讀一次 `canCreateEvent` 存成 `_canCreateEvent`，之後不再更新。
  - 個人頁 `profile_screen.dart` 的 `_buildMoreSection` 是「個人資料設定／我發起的活動／我參加的活動／我按讚的內容」的 `profileNavRow` 清單。
  - 貼文詳情 `forum_detail_screen.dart` 有 `PopupMenuButton`（自己：編輯／刪除；別人：檢舉）；公開個人頁 `public_profile_screen.dart` 有 `_menuItemsFor`（封鎖、檢舉等）；活動詳情 `event_detail_screen.dart` 有發起人操作列。
  - 推播：`FcmService`（`lib/services/fcm_service.dart`）各類型各有 `_parseXxx`，處置推播（`type: moderation`）已由 `_showModerationNotice` 處理。
  - JWT 續期（H1 前提 B6）已由 `SessionService.restore()` 在啟動時處理。
  - 文章內文用 `flutter_markdown_plus` 渲染。
- 這次會動到的既有部位：`lib/core/constants/api.dart`；`lib/models/user_model.dart`；新增 `lib/services/admin_service.dart`、`lib/models/admin_models.dart`、`lib/screens/admin/`；`lib/screens/profile/profile_screen.dart`；`lib/screens/events/events_screen.dart`、`event_detail_screen.dart`；`lib/screens/forum/forum_detail_screen.dart`、`widgets/forum_comment_tile.dart`；`lib/screens/friends/public_profile_screen.dart`；`lib/services/fcm_service.dart`；`integration_test/api_inspector_test.dart`、`test/fixtures/api/`。
- 已定案的技術前提：
  - 後台做在 App 裡，`GET /api/me` 的 `role == 'admin'` 才顯示入口；沿用 App 登入憑證呼叫 `/api/admin/*`。
  - 後台端點一律用 uid 指定使用者（`userRef.ts`：「管理員後台照舊用 uid」）；列表端點用 `limit`＋`cursor`，讀 `page_info`。
  - 所有後台錯誤直接顯示後端 `message`；`SELF_INVOLVED`、`SAME_ADMIN` 等不加「操作失敗：」前綴、不當成一般錯誤。
  - 文章後台照後端現有設計做，限制列明：後端沒有列出草稿／已下架文章的端點，App 內只能找到已發布文章；封面圖只能貼上已在 GCS 的 HTTPS 網址，沒有上傳功能。
- 已知限制：
  - `FRIEND_CODE_ENFORCE` 開啟後，`GET /api/users/:friend_code` 不再回 uid，管理員無法用好友碼取得新對象的 uid——影響 T-04 設定新角色、T-12 查帳、T-16 更正生日，三卡先標卡住，待使用者與後端討論（見待決 1）。
  - 違規區二審必須是開案以外的另一位管理員，正式環境至少要有兩位管理員才走得完 T-02→T-03。
  - 錄 fixture 需要登入帳號為 admin；模擬器會跳 Google 帳號選擇，所有後台 GET 集中一次錄，開錄前先提醒使用者。

## 任務卡

### T-01 管理員能從個人頁進入後台並看到待審檢舉

**使用者價值**：管理員不用再靠 curl 與短時效憑證，在 App 裡就能看到有哪些檢舉等著處理；一般使用者完全看不到後台。

**範圍**
- 包含：後台入口、後台首頁（功能清單）、檢舉佇列（唯讀，依狀態切換）、`AdminService` 與共用錯誤處理、後台所有 GET 的 inspector 錄製與契約測試。
- 不包含：審核動作（T-02）、其他後台功能（各自的卡）。

**驗收條件**
- [ ] `role == 'admin'` 時個人頁「更多」區塊出現「管理後台」；其他角色看不到。角色在 `userNotifier` 更新後入口即時出現或消失。
- [x] 後台首頁列出各功能入口，尚未實作的功能不顯示。
- [x] 檢舉佇列預設顯示 `pending`，可切換 `reviewed`／`dismissed`／`actioned`；每筆顯示類型、檢舉理由、檢舉人、時間與預覽：貼文／留言／私訊用 `target_preview`，通話用 `target_call`，個人檔案用 `target_profile`（暱稱、自介、頭像），`target_deleted` 為 true 時標示「內容已刪除」。
- [x] 下拉可重新整理，捲到底用 `page_info.next_cursor` 載下一頁。
- [x] 後台任一請求回 `403 ADMIN_ONLY` 時顯示 `message`、重抓 `/api/me` 並退出後台。
- [ ] 精簡模式字級與間距正確。

**實作設計**
- 前端：
  - `UserModel` 加 `bool get isAdmin => role == 'admin'`。
  - `profile_screen.dart` 的 `_buildMoreSection` 以 `ValueListenableBuilder` 監聽 `UserService.userNotifier`，`isAdmin` 時加一列 `profileNavRow`「管理後台」。
  - `ApiConfig` 新增後台路徑區塊（`/api/admin/...`）。
  - 新增 `lib/services/admin_service.dart`：各後台端點一個靜態方法；列表方法回 `(items, PageInfo)`，沿用既有 `PageInfo`。
  - 新增 `lib/models/admin_models.dart`：`AdminReport`（含 `targetCall`、`targetProfile` 子結構）。
  - 新增 `lib/screens/admin/admin_home_screen.dart`（功能清單）、`admin_reports_screen.dart`（狀態分頁＋列表）。
  - 共用錯誤處理 `lib/screens/admin/admin_error.dart`：`ADMIN_ONLY` → 顯示 message、`fetchMe(forceRefresh: true)`、`popUntil` 離開後台；其餘錯誤顯示 `message` 原文。
  - 返回鍵用 `AppBackButton`，文字用 `AppTypography` 的 `*Style()`。
- 測試：`api_inspector_test.dart` 以 admin 帳號加入所有後台 GET 的 raw 測試（`forum/reports`、`moderation/cases`、`users/roles`、`mutes`、`banned-words`、`question-reports`、`millet/transactions`、`millet/reconcile`），一次錄進 `test/fixtures/api/`；本卡先補檢舉佇列的契約測試，其餘由各卡補。

**依賴**：無

**風險 / 待決**：正式環境的檢舉佇列可能是空的，錄不到 `target_call`／`target_profile` 有值的樣本時，這兩個子結構依規格手寫測試資料。

**進度**：實作完成

### T-02 管理員能駁回或判定檢舉成立

**使用者價值**：管理員在 App 裡就能完成一審，違規內容立刻隱藏並送進違規區等二審。

**範圍**
- 包含：檢舉詳情的「駁回」「判定成立」、個人檔案檢舉的重設欄位選擇、結果與錯誤呈現。
- 不包含：二審（T-03）。

**驗收條件**
- [x] 待審檢舉可「駁回」或「判定成立」，送出前二次確認；成功後該筆從 `pending` 列表移除。
- [x] 判定成立後顯示已開案（案件編號），`auto_closed_report_ids` 非空時顯示「同一則內容另有 N 筆檢舉一併結案」並從列表移除這些筆。
- [x] 個人檔案檢舉判定成立時可勾選要重設的欄位（暱稱、自我介紹、頭像），預設三項全選，至少一項才能送出。
- [x] 駁回且 `auto_lifted_mute_id` 有值時提示「已自動解除該使用者的檢舉禁言」。
- [x] `403 SELF_INVOLVED` 顯示後端 `message`（「這個案件的當事人是你自己，請交給其他管理員審核」），該筆保留在列表。
- [x] `409 ALREADY_REVIEWED` 顯示 message 並重新整理列表；`409 TARGET_NOT_FOUND` 顯示 message，提示改用駁回。

**實作設計**
- 前端：
  - `AdminService.resolveReport(id, action, {resetFields})` → `POST /api/admin/forum/reports/:id/resolve`，回 `case`、`autoClosedReportIds`、`autoLiftedMuteId`。
  - `admin_reports_screen.dart` 點單筆開 `admin_report_detail_screen.dart`：完整預覽＋底部兩個按鈕；個人檔案類型多一組 `CheckboxListTile`。
  - 錯誤走 T-01 的共用錯誤處理。

**依賴**：T-01（後台入口、`AdminService`、檢舉列表）

**進度**：實作完成

**使用者價值**：違規要經第二位管理員確認才會記次；誤判可以撤銷並恢復內容。

**範圍**
- 包含：違規區列表（`pending`／`confirmed`／`overturned`）、案件詳情、確認／撤銷與備註。
- 不包含：解鎖帳號（T-08）。

**驗收條件**
- [x] 違規區依狀態切換，每筆顯示類型、被處置者暱稱與狀態、來源（管理員刪除／使用者檢舉／自動禁言）、理由、開案者與時間、預覽。
- [x] 預覽依類型呈現：貼文標題＋內文、留言內文、私訊內文＋時間、通話雙方與時間、活動標題＋說明＋時間、自動禁言範圍與到期時間；個人檔案案件並列「重設前（`snapshot`）」與「目前」。
- [x] 待審案件可「確認違規」或「撤銷」，可填 500 字內備註，送出前二次確認。
- [x] 確認成功後顯示結果：第幾次違規、禁言到何時或已鎖帳號、連帶取消的活動數；撤銷成功顯示「已恢復內容」，自動解除禁言時一併說明。
- [x] `403 SAME_ADMIN`、`403 SELF_INVOLVED` 顯示後端 `message`，案件保留在列表；`409 CASE_ALREADY_REVIEWED` 顯示 message 並重新整理。
- [x] 已審案件顯示審核者、時間、備註與 `strike_number`。

**實作設計**
- 前端：
  - `AdminService.fetchCases(status, cursor)`、`reviewCase(id, decision, note)`。
  - `AdminCase` model：`preview` 依 `target_type` 解析成不同子型別，`snapshot` 為 `Map<String, dynamic>?`。
  - 新增 `admin_cases_screen.dart`、`admin_case_detail_screen.dart`；後台首頁加「違規區」入口。
- 測試：補違規區 fixture 的契約測試。

**依賴**：T-01（後台入口、`AdminService`）

**風險 / 待決**：錄 fixture 時違規區可能只有部分類型，缺的類型依規格手寫測試資料。

**進度**：實作完成

### T-04 管理員能設定帳號角色，當事人的入口即時跟著變

**使用者價值**：管理員在 App 裡就能指定活動發起人或其他管理員，不必請後端改資料庫；被調整的人不用重開 App，「發起活動」「管理後台」入口就會跟著出現或消失。

**範圍**
- 包含：角色清單、以好友碼查人並設定角色、`account_role` 推播處理、「發起活動」按鈕即時反映角色。
- 不包含：無。

**驗收條件**
- [ ] 後台「角色管理」列出目前的管理員與活動發起人（暱稱、好友碼、角色），管理員排前面。
- [ ] 清單上的人可改角色；另可輸入好友碼查人，確認暱稱後選角色（一般使用者／活動發起人／管理員）並填 1～200 字理由才能送出。
- [ ] 成功後清單更新；`changed: false` 時提示「角色未變更」。
- [ ] `403 SELF_ROLE_CHANGE`、`409 USER_UNAVAILABLE`、`404 USER_NOT_FOUND` 顯示後端 `message`。
- [ ] 當事人前景收到 `account_role` 推播時顯示通知內容並重抓 `/api/me`；「發起活動」按鈕與「管理後台」入口不重開 App 就依新角色變化。背景點通知打開 App 後同樣重抓。
- [ ] `FRIEND_CODE_ENFORCE` 開啟後仍能以好友碼設定新對象的角色。

**實作設計**
- 前端：
  - `AdminService.fetchRoleUsers()`、`setRole(uid, role, reason)` → `PATCH /api/admin/users/:uid/role`。
  - 以好友碼查人沿用既有公開個人頁 API（`GET /api/users/:friend_code`）取 `uid`。
  - 新增 `admin_roles_screen.dart`、設定角色底板。
  - `FcmService` 加 `_parseAccountRole`：前景 SnackBar 顯示 title／body，並呼叫 `UserService.fetchMe(forceRefresh: true)`；背景點擊同樣重抓。
  - `events_screen.dart` 的 `_canCreateEvent` 改為監聽 `UserService.userNotifier`。
- 測試：`account_role` payload 依規格手寫；角色清單 fixture 補契約測試。

**依賴**：T-01（後台入口、`AdminService`）

**風險 / 待決**：錄 fixture 會真的改角色，`PATCH` 不錄，依規格手寫。

**進度**：卡住
- 卡在：開關開啟後 `GET /api/users/:friend_code` 不再回 uid，後台端點又只收 uid，以好友碼設定新對象會失效；過渡期可用。待使用者與後端討論（待決 1）。
