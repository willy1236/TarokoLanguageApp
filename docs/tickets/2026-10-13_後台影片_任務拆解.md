## 現況與前提

- 技術棧：Flutter（`lib/`），手機 App 與網頁版同一份程式。後端已上線（主服務 `00255-fug`，PR #85），本次只動前端。
- 既有相關機制：
  - 後台入口 `lib/screens/admin/admin_home_screen.dart` 的 `_entries` 清單；畫面共用 `AdminScaffold`、`pushAdmin`、`handleAdminError`（`admin_widgets.dart`、`admin_error.dart`）。
  - API 呼叫集中在 `lib/services/admin_service.dart`（`ApiClient.get/post/patch`，列表回 `AdminPage<T>`＋`PageInfo`，`limit`＋`cursor`），模型在 `lib/models/admin_models.dart`。`ApiClient` 只打自家後端（`ApiConfig.baseUrl + path`），**沒有對外部網址送原始 `PUT` 的方法**。
  - 分類：`CategoryService`（`lib/services/category_service.dart`）提供快取與 `labelOf`；`AdminService.fetchCategories(CategoryModule)`。文章表單 `admin_article_form_screen.dart` 內嵌「下拉＋新增分類」（`_newCategoryOption`、`_typingNewCategory`、長度上限 `categoryLabelMax`（`lib/models/content_category.dart`）），**目前只在 `feat/categories` 分支，尚未合進 `master`**。
  - 部落欄位已有共用元件 `lib/shared/widgets/related_tribe_field.dart`（`RelatedTribeField`）、`tribe_picker_sheet.dart`。
  - 選檔：依賴裡只有 `image_picker`（`pickVideo` 只開相簿；iOS 端用 PHPicker、`preferredAssetRepresentationMode = Current`，拿得到原始檔不轉檔）。沒有 `file_picker`、沒有背景上傳套件。
  - 測試：`test/fixtures/api/*.json` 錄製回應、`test/contract/api_contract_test.dart` 對模型做契約測試、`test/screens/admin/` 畫面測試。
- 這次會動到的既有部位：`admin_home_screen.dart`（加入口）、`admin_service.dart`、`admin_models.dart`、`admin_article_form_screen.dart`（抽出分類欄位）、`core/constants/api.dart`（端點常數）、`pubspec.yaml`（`file_picker`、背景上傳套件）、Android manifest（背景上傳時）。
- 已定案的技術前提：
  - 只有管理員看得到；手機與網頁都要做（A54）。
  - YouTube＝貼網址、mp4／mov＝選檔案；其他網址後端回 `INVALID_YOUTUBE_URL`。
  - 影片檔直傳雲端 `session_url`（GCS resumable）：分段 `PUT`＋`Content-Range`，每段為 `chunk_size_multiple`（256KiB）倍數，建議 8MB；中間段 `308`、最後一段 `200`／`201`；查進度送空內容＋`bytes */{總大小}`；工作階段一週有效；不可整檔讀進記憶體。
  - 上傳完成後影片仍是「處理中」，由後端轉檔後自動上架；處理中的影片靠下拉重整看狀態，不做自動輪詢。
  - 列表回應沒有分類 `label`，顯示名稱用 `CategoryService.labelOf(CategoryModule.videos, …)`。
  - 沒有內容的 `POST`（下架）要帶 `Content-Length: 0`；`http` 套件會自動帶，沿用 `ApiClient.post` 即可。
  - 這一輪做背景上傳（T-06）。
  - 手機能從相簿或「檔案」選影片（加 `file_picker`）。
  - 上傳由 App 層級的上傳服務執行，可以離開進度頁，影片管理列表看得到進度；一次只傳一支，上傳中再選檔會提示等目前這支傳完。
  - 網頁版重新整理後，重選同一個檔案（檔名與大小相符）就從斷點續傳。
  - 開工前提：`feat/categories` 先合進 `master`（T-01 要從那裡的文章表單抽元件）。

**範圍**

- 不包含：YouTube 預覽、選檔（T-03、T-04）；送出 API（各功能卡）。

**驗收條件**
- [x] 文章表單的分類下拉、「＋新增分類」、新分類長度檢查、清單載入失敗重試，行為與抽出前相同（既有 `test/screens/admin/` 文章表單測試全過）
- [x] 分類欄位給 `CategoryModule.videos` 時讀影音分類清單
- [x] 影片資訊欄位：標題空白時顯示錯誤；說明超過 2000 字顯示錯誤；分類未選時顯示錯誤；部落可不選、可清除

  - `AdminCategoryField({required CategoryModule module, String? initial, required AdminCategoryController controller, bool selectFirst = true, bool seniorMode = false})`；`controller.value → String?`（下拉選的值或新輸入的名稱，未選為 null）、`controller.isNew → bool`、`controller.isLoaded → bool`（分類清單已載入）、`controller.validate() → String?`（錯誤文字）。

  - `AdminVideoMeta { String? title; String? description; String category; int? tribeId; }`，在 `lib/models/admin_video_meta.dart`（2026-10-14 決定拆成兩個輸出）：
    - `toJson()` 給建立用：只輸出有值的欄位，空白字串視同沒填。
    - `patchFrom(AdminVideoMeta original) → Map<String, Object?>` 給 PATCH 用：只輸出和原值不同的欄位；說明、部落清空時輸出 `null`；標題不能清空（後端必填），沒填就不送；沒有改動回空 Map。
  - `titleRequired` 給 T-03 用：YouTube 可嵌入影片的標題可留空由後端帶入。

### T-03 管理員能貼 YouTube 網址，預覽後上架

**使用者價值**：管理員自己就能把 YouTube 影片加進影音頁，不必等工程師跑匯入腳本。

**範圍**

- 不包含：「選擇檔案」來源（T-04，本卡先把來源切換做出來，檔案那一側留給 T-04）。

**驗收條件**
- [x] 貼上網址後自動預覽：顯示縮圖、標題預先填好且可改
- [x] `exists_video_id` 有值時提示「這支影片已經上架過」，並不讓上架
- [x] `embeddable: false` 時提示「這支影片不允許在 App 裡播放，會改成開 YouTube」，標題變必填

- [x] 按「上架」成功後回到列表，新影片在最上面且是「已上架」；上架時 `409 VIDEO_EXISTS` 顯示已上架提示

  - `admin_videos_screen.dart` 右上角「上傳影片」，上架成功回來時以 `reload()` 重抓第一頁並保留目前篩選。

### T-08 管理員能下架影片

**使用者價值**：有問題的影片管理員自己下架，不必請工程師跑 `video-archive.mjs`。

**範圍**
- 包含：列選單「下架」（非已下架才出現）、確認對話框、刪檔沒刪乾淨的重試提示。

**驗收條件**
- [x] 按下架先跳確認「下架會刪除播放檔，無法復原」，取消不送出
- [x] 成功後該列變「已下架」
- [x] 回 `files_deleted: false` 時提示「已下架，但檔案沒刪乾淨，請再按一次」，且已下架的這一列仍提供「再刪一次檔案」

**實作設計**
- 後端：`POST /api/admin/videos/:id/archive`（無內容，`ApiClient.post` 帶空 body）回 `{ ok, files_deleted }`。
- 前端：
  - `AdminService.archiveVideo(int id) → bool`（回 `files_deleted`）；確認沿用後台既有對話框樣式。`files_deleted: false` 的狀態只存在本次畫面記憶體，重開列表看不到（後端沒有欄位記錄），由再按一次解決。

### T-06 手機切到別的 App 或鎖螢幕時上傳繼續進行

**使用者價值**：管理員按下上傳後可以把手機放著或去做別的事，不必盯著畫面 10～30 分鐘。

**範圍**
- 包含：手機上傳改由系統背景傳輸執行（iOS background `URLSession`、Android 14 以上 UIDT），含 Android 通知列進度與完成通知。
- 不包含：
  - 網頁版、桌面版（維持 T-04 的前景分段）。
  - 背景期間的重送：背景中失敗不重排，回到前景才查進度接著傳（2026-10-14 決定 D）。

**驗收條件**
- [ ] iOS：上傳中按 Home 或鎖螢幕 5 分鐘再回來，進度有前進
- [ ] Android 14 以上：上傳中切走，通知列顯示上傳進度；完成時通知「上傳完成」
- [ ] 背景中斷網再恢復、或系統中止上傳：回到 App 時自動查進度，從斷點重排剩下的部分，不從 0 開始
- [ ] App 被滑掉再打開：依 T-05 續傳，不會同時有兩個 PUT 打同一個工作階段
- [ ] 上傳 2GB 檔案，Android 不出現前景服務、不 crash（含 UIDT 排程失敗退回 WorkManager 的情況）

**實作設計**
- 送法：每次用一個 `PUT` 把剩下的部分送到檔尾（`Content-Range: bytes {offset}-{size-1}/{size}`），交給 `background_downloader` 的 `UploadTask`（`httpRequestMethod: 'PUT'`、`post: 'binary'`、`retries: 0`；offset 大於 0 時帶 `Range: bytes={offset}-{size-1}` 指定檔案範圍）。因為一定送到檔尾，成功只會是 `200`／`201`；其他結果（含 `308`、網路錯誤）一律當失敗。手機從開始上傳就走這個送法，不分前景、背景。
- 只在前景排程，這是唯一會排 task 的三個時機：
  1. 管理員按下上傳（T-04）
  2. App 回到前景時，發現這支上傳已失敗（`resumeFromBackground` 取回背景期間的狀態）
  3. 進影片管理續傳（T-05）

  每次排程前都先用前景 http 查進度、取得 offset。從背景重排的程式路徑整個不做，所以不需要 `quietGroup`、不用依前景或背景切換 priority，也不做停滯監看：請求逾時交給系統（iOS `timeoutIntervalForRequest`、`resourceTimeout` 24 小時；Android 用套件的 connection timeout）。
- 一支影片同時只有一個 task：task id 用 `{videoId}-{時間}`；排新 task 前，取消同一支影片所有殘留的 task，等收到 `canceled` 才繼續。放棄上傳時也一樣先取消，再刪暫存檔。
- iOS：
  - offset 為 0 時直接從原檔整檔上傳，不會複製。
  - offset 大於 0 時，套件會把剩下的部分複製成暫存檔。因為只在前景排程，複製一定是在前景完成。複製前先檢查剩餘空間（剩下的大小加 200MB），不夠就顯示「手機空間不足，需要約 X GB 才能續傳」；複製期間進度頁顯示「準備續傳中…」。
- Android 14 以上：task 用 `priority: 0` 並設定通知（`configureNotificationForGroup` 的 running／complete，`progressBar: true`），走 UIDT。套件的 `UIDTJobService` 寫死 `runInForeground = true`，不受 9 分鐘限制。**不設定 `Config.runInForeground`**，這樣 UIDT 排程失敗退回 WorkManager 時不會呼叫 `setForeground`，對應 B-1。
- Android 13 以下：不走背景，沿用 T-04 的前景分段送法（決定 E）。進度頁提醒文案維持「上傳完成前請讓 App 保持開啟」。
- 2026-10-14 決定：
  - A：Android 不用前景服務，也不做 Play 前景服務申報。
  - ~~B：背景一次送完剩下全部~~：改為「每次送到檔尾、只在前景排程」，見上文。原寫的「iOS 不需暫存檔」不成立：套件 9.5.9 在 offset 大於 0 時會複製剩下的部分（`BDPlugin.swift` `createTempFileWithRange`）。
  - C：鎖 `background_downloader` 9.5.9（9.6 需要 Flutter 3.47）。
  - D：背景期間不重送，操作都回前景處理。
  - E：Android 13 以下不支援背景上傳，列為已知限制。不分段時，WorkManager 單一請求最多約 9 分鐘（套件 `taskTimeoutMillis`），傳不完 2GB；改用 `dataSync` 前景服務會違反決定 A。
