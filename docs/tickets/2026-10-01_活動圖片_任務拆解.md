## 現況與前提

- 技術棧：Flutter（Android／iOS 為主），HTTP 走 `ApiClient`，錯誤統一成 `ApiException`（有 `isMuted`，`toString()` 已把禁言到期時間接在後端訊息後面）。
- 既有相關機制：
  - 活動畫面都在 `lib/screens/events/`，資料走 `EventService`（`lib/services/event_service.dart`），模型是 `EventDetail`／`EventSummary`（`lib/models/event_model.dart`）。端點常數在 `lib/core/constants/api.dart`（`eventDetail(id)` 等）。
  - 建立與編輯共用 `EventComposeScreen`（`editing` 為 null 是建立）。頂端有一塊 `_buildCoverPlaceholder`：漸層底＋鎖頭，文字「活動封面（尚未開放）」，點了跳「活動封面上傳功能尚未開放」。`EventService.createEvent` 回 `(id, tribeNotifyLimited)`，送出成功後 `pop(true)`。
  - 編輯入口只有詳情頁發起人操作列（`event_action_bar.dart` 的 `_hostActions`），條件是 `startsAt` 還沒到；活動已取消或已結束時，操作列整條換成一顆停用按鈕，發起人沒有任何管理入口。PATCH 對已取消、已開始的活動回 409。
  - 論壇發文已有整套多圖流程可沿用：`ImagePicker().pickMultiImage(limit:)` → `compressImageForUpload`（`lib/shared/utils/upload_image.dart`，長邊 1920、JPEG 85，Web 走 bytes）→ 檢查 5 MB → `MultipartFileData` → `ApiClient.postMultipart`。已選未上傳的圖用 `MemoryImage` 預覽。
  - 全螢幕檢視 `ForumImageViewer`（`lib/screens/forum/widgets/forum_image_grid.dart`）收 `List<ImageProvider>` 與 `initialIndex`，可左右滑、雙指縮放。同檔的圖片元件有 `onImageExpired`：破圖時對同一網址只回報一次，呼叫端（`forum_detail_screen.dart` 的 `_onImageExpired`）重打 API 換新網址，有次數上限。
  - 網路圖用 `cached_network_image`，目前沒有任何地方設 `cacheKey`，快取以完整網址為鍵；簽章網址每次重新取得都會變，等於每 15 分鐘重抓一次。
  - 活動卡片：
    - `EventFeaturedCard`（`widgets/event_cards.dart`，活動列表第一筆）：上方 120 高的漸層＋織紋＋山形，左上狀態標籤。
    - `EventList` 的列（同檔，活動列表其餘筆）：左邊 56 寬的分類色日期塊，右邊分類標籤、標題、地點、人數。
    - `EventStatusTile`（`widgets/event_status_tile.dart`，我發起的、我參加的）、`event_liked_bookmarked_list.dart` 的 `_EventListItem`、`event_search_screen.dart` 的 `_EventResultTile`、廣場的 `PlazaMiniEventCard`（`lib/screens/plaza/widgets/plaza_cards.dart`，200 寬）。
  - 詳情頁 `EventDetailScreen` 是 `CustomScrollView`：`EventDetailHero`（210 高漸層＋織紋，疊返回鈕、分類、日期、標題；已取消、已結束改灰色漸層）→ `EventDetailBody` → 檢舉／下架 → 底部 `EventActionBar`。
  - `integration_test/api_inspector_test.dart` 已有活動各列表的 raw 測試，沒有圖片端點。
- 這次會動到的既有部位：`lib/core/constants/api.dart`、`lib/models/event_model.dart`、`lib/services/event_service.dart`、`lib/screens/events/event_compose_screen.dart`、`lib/screens/events/event_detail_screen.dart`、`lib/screens/events/widgets/event_detail_hero.dart`、`lib/screens/events/widgets/event_action_bar.dart`、`lib/screens/events/widgets/event_cards.dart`、`lib/screens/events/widgets/event_status_tile.dart`、`lib/screens/events/event_liked_bookmarked_list.dart`、`lib/screens/events/event_search_screen.dart`、`lib/screens/plaza/widgets/plaza_cards.dart`、`integration_test/api_inspector_test.dart`。
- 已定案的技術前提：
  - 上傳 `POST /api/events/:id/images`（multipart，欄位 `images`，可多張），刪除 `DELETE /api/events/:id/images/:imageId`，都只限發起人，成功都回該活動目前全部的 `images`（`[{id, url}]`，依上傳順序）。
  - 每場最多 6 張、每張 5 MB 內、JPEG／PNG／WebP；一次上傳全部成功或全部失敗。
  - 不經審核、上傳即公開；伺服器重新輸出並去掉 GPS 等中繼資料，App 不另外處理。
  - 第一張就是封面，沒有調整順序的 API；要換封面得刪掉前面的再重傳。
  - 詳情多 `images`（沒圖為 `[]`）與 `cover_image_url`；`/events`、`/events/mine`、`/events/joined`、`/events/likes`、`/events/bookmarks`、`/events/search` 每筆多 `cover_image_url`。
  - 網址 15 分鐘到期，可快取圖片內容、不長期存網址；過期（403）就重新取得詳情或列表。
  - 已取消、已結束的活動也能補照片，已刪除的不行。
  - 建立活動照舊用 JSON 建立，拿到 `id` 再上傳；圖片失敗不影響活動，提示「活動已建立，圖片可以稍後在編輯頁補上」。
  - 錯誤都有 `error.message` 可直接顯示；刪除回 `404 IMAGE_NOT_FOUND` 視為成功。
  - 上傳前在 App 端縮圖，沿用論壇的 `compressImageForUpload`。
  - 發起人在詳情頁頂端的輪播上直接新增、刪除，當下就生效；這是活動開始、取消、結束後的唯一入口。
  - 編輯頁的圖片跟其他欄位一樣，按「儲存」才送出，按返回就放棄。
  - 詳情頁有圖時以輪播取代頂端漸層，文字疊在照片上。
  - 精選大卡、廣場小卡以照片取代漸層；其他列表列保留日期塊，右側加小方形縮圖。
  - 這次自己升 `1.0.0+17` 單獨發版（2026-10-02 決定，資料來源與授權 A3 之後升 `+18`）。

## 任務卡

### T-01 發起人能在活動詳情頁新增、刪除圖片，所有人都看得到輪播

**使用者價值**：發起人能放上活動海報、場地照片，活動開始、結束或取消後也能補上現場照片；看活動的人在詳情頁頂端就看得到這些照片。

**範圍**
- 包含：兩支圖片端點的 inspector 測試、`EventDetail.images` 解析、service、詳情頁頂端的輪播（取代 hero 漸層）、發起人在輪播上的新增與刪除。
- 不包含：全螢幕檢視、網址過期換新、快取鍵（T-02）；發起活動頁選圖（T-03）；編輯頁增刪（T-04）；列表封面（T-05）。

**驗收條件**
- [x] 有圖片的活動，詳情頁頂端顯示照片輪播，可左右滑，有第幾張的指示（例如 2／5），只有一張時不顯示指示
- [ ] 返回鈕、分類、日期、標題、已取消／已結束標示照舊疊在照片上，亮色照片上也讀得清楚
- [x] 沒有圖片的活動，一般使用者看到的頂端和現在一樣
- [x] 發起人在沒有圖片的活動頂端看到「新增照片」入口；有圖片時看到新增按鈕與目前這張的刪除按鈕
- [ ] 未開始、進行中、已取消、已結束的活動，發起人都能新增、刪除
- [x] 可一次選多張；上傳成功後輪播立即更新，順序與後端回應一致，第一張就是封面
- [x] 已有 4 張時挑選器最多只讓選 2 張；滿 6 張時新增按鈕停用並說明上限
- [x] 刪除前先確認；刪除後輪播停在相鄰的一張，刪到沒圖時回到漸層樣式
- [x] 刪除回 404 `IMAGE_NOT_FOUND` 時當作已刪除，畫面同步移除，不顯示錯誤
- [x] 某張壓縮後仍超過 5 MB 或無法處理時，提示檔名並略過那張，其他照常上傳
- [x] 上傳回 400／403 時顯示後端 `error.message`，禁言（`MUTED`）時訊息含禁言到期時間；輪播維持上傳前的樣子
- [x] 上傳、刪除進行中按鈕停用並顯示進行中狀態，不會重複送出
- [x] 非發起人看不到任何新增、刪除的操作
- [x] 返回列表後，列表會刷新（沿用詳情頁有變更就回 `true` 的機制）
- [x] 長輩模式下按鈕與指示文字照字級放大，不爆版

**實作設計**
- 前端：
  - `ApiConfig` 加 `eventImages(id)`、`eventImage(id, imageId)`。
  - `event_model.dart` 加 `EventImage { id, url }`；`EventDetail` 加 `images`（缺欄位時為空清單）與 `coverImageUrl`。
  - `EventService` 加 `uploadImages(eventId, List<MultipartFileData>) → List<EventImage>` 與 `deleteImage(eventId, imageId) → List<EventImage>`，都回後端給的完整清單；`deleteImage` 遇到 `IMAGE_NOT_FOUND` 不丟錯，回傳方式實作時決定。上限常數 `imageMaxCount = 6`、`imageMaxBytes` 放在 `EventService`，比照 `ForumService`。
  - 挑圖與壓縮抽成一個共用函式（例如 `lib/shared/utils/pick_images.dart`）：`pickMultiImage(limit:)` → `compressImageForUpload` → 5 MB 檢查 → 回 `List<MultipartFileData>`，略過的檔名交給呼叫端提示。論壇 `_pickImages` 可改用它，也可留到之後；T-03、T-04 會用到。
  - 新增 `widgets/event_image_carousel.dart`：`PageView` 加頁數指示，吃 `images` 與 `isHost`；`isHost` 時在角落疊新增與刪除按鈕，上傳、刪除的狀態與錯誤提示由它自己管，清單變動時回呼。
  - `EventDetailHero`：有圖時以輪播取代漸層與織紋，上面加一層下暗上透的遮罩，文字層照舊；沒圖時維持漸層，發起人多一個「新增照片」入口。文字層不能吃掉左右滑的手勢。
  - `EventDetailScreen` 收到輪播的清單變動後更新 `_event` 的 `images` 並 `_markChanged()`。
  - `api_inspector_test.dart` 加上傳與刪除的 raw 測試：在錄製帳號自己的測試活動上傳一張再刪掉，確認 `201 { images }`、`200 { ok, images }` 的形狀；另錄一次 `GET /api/events/:id` 確認 `images`、`cover_image_url` 實際格式。

**依賴**：無

**風險 / 待決**
- inspector 會在正式後端真的上傳、刪除，要用錄製帳號自己發起的活動，測完刪乾淨。錄製要人點 Google 帳號，跟 T-05 要錄的列表集中一次錄。
- hero 高度 210 對照片偏矮，可視情況拉高，只要文字層位置不亂。

**進度**：實作完成（2026-10-02）
- commit：feat/event-images 32c699f..0eb804c
- 未驗：亮色照片上文字可讀性、未開始／進行中／已取消／已結束四種狀態下實際增刪（需實機）；圖片端點的原始格式還沒對真後端錄過（錄製帳號沒有自己發起的活動，2026-10-02 決定先照文件寫、實機驗證時再錄）
- 實作決定：有圖時 hero 拉高到 280；挑圖函式改為只回 JPEG bytes，`uploadImages` 收 bytes、自己包成 multipart；`deleteImage` 遇 `IMAGE_NOT_FOUND` 改從詳情取目前圖片回傳

### T-02 看活動圖片能點開全螢幕，放久了也不會破圖

**使用者價值**：看海報細節或現場照片時能放大；停在頁面一陣子後再滑，照片仍正常顯示，也不會每次都重新下載。

**範圍**
- 包含：點輪播開全螢幕、網址過期自動換新、破圖手動重試、以圖片 id 當快取鍵。
- 不包含：輪播本身與發起人操作（T-01）；列表封面的過期處理（T-05）。

**驗收條件**
- [x] 點輪播任一張進全螢幕，從被點的那張開始，可左右滑、雙指縮放，返回回到詳情頁
- [x] 發起人點照片同樣進全螢幕，不會誤觸刪除
- [ ] 停在詳情頁超過 15 分鐘後滑到還沒載入的圖，會自動重新取得詳情並顯示，不出現永久破圖；自動重試有次數上限
- [x] 破圖時點一下可手動重試，不受自動重試上限限制
- [ ] 同一張圖在網址換新後不重新下載（從快取顯示）

**實作設計**
- 前端：
  - 輪播點擊開 `ForumImageViewer`（傳 `CachedNetworkImageProvider`）。
  - 快取鍵：`CachedNetworkImage` 與 `CachedNetworkImageProvider` 設 `cacheKey: 'event-image-<id>'`。T-05 的封面只有網址沒有 id，改用去掉 query string 的網址路徑當鍵；兩者抽成同一個小函式。
  - 過期處理比照論壇：破圖時對同一網址只回報一次，`EventDetailScreen` 收到後 `_silentRefresh()`，自動重試設上限；手動點擊不受上限。可考慮把 `forum_image_grid.dart` 裡「破圖回報一次」的元件抽到 `lib/shared/widgets/` 讓兩邊共用。

**依賴**：T-01（輪播元件）

**風險 / 待決**：若共用元件改到論壇，論壇的快取行為不變（論壇沒設快取鍵），抽出時只搬「回報一次」的邏輯。

**進度**：實作完成（2026-10-02）
- commit：feat/event-images 32c699f..0eb804c
- 未驗：停留超過 15 分鐘後的實際換網址、換網址後不重新下載、雙指縮放（需實機）
- 實作決定：快取鍵不用 `event-image-<id>`，改與 T-05 共用「去掉 query 的物件路徑」，詳情第一張與列表封面共用快取；自動重取每頁最多 3 次；論壇附圖元件未改動

### T-03 發起活動時能一起選圖片

**使用者價值**：發起人不必先建好活動再回詳情頁補圖，一次就能把活動連同海報發出去。

**範圍**
- 包含：發起活動頁的圖片欄位（取代「活動封面（尚未開放）」鎖頭區塊）、建立成功後上傳、上傳失敗的提示。
- 不包含：編輯頁（T-04）。

**驗收條件**
- [x] 發起活動頁原本的鎖頭區塊換成圖片欄位，可選最多 6 張，選完顯示縮圖、可移除、可點開全螢幕預覽；第一張標示「封面」
- [x] 發布後先建立活動、再上傳圖片；全部成功顯示「活動已發起」
- [x] 活動建立成功但圖片上傳失敗時，活動照常建立並返回列表，提示「活動已建立，圖片可以稍後在編輯頁補上」
- [x] 活動建立失敗時不上傳圖片，留在表單，已選的圖還在
- [x] 送出中按鈕停用，不會重複建立活動或重複上傳
- [ ] 部落推播次數用完的提示仍正常出現；與圖片失敗同時發生時兩件事都有交代
- [x] 沒選圖時流程與現在完全一樣

**實作設計**
- 前端：
  - 新增 `widgets/event_images_field.dart`：表單用的圖片欄位，持有「已存在的圖片」（建立模式為空）與「待上傳的 bytes」，用 T-01 的挑圖函式加圖、`MemoryImage` 預覽、上限算兩者合計；本身不打 API，由表單在送出時讀取。T-04 再加上「標記刪除既有圖片」。
  - `EventComposeScreen._submit()` 建立模式：`createEvent` 拿到 `id` → 有圖才 `uploadImages(id, …)` → 依結果決定 SnackBar 文字 → `pop(true)`。圖片錯誤單獨接住，不讓整個 `_submit` 進 catch 而留在表單。
  - 推播次數用完與圖片失敗同時發生時，合成一則或依序顯示，實作時決定。

**依賴**：T-01（`uploadImages` 與挑圖函式）

**風險 / 待決**：活動已建立、圖片還在上傳時使用者關掉 App，活動會沒有圖；提示語已涵蓋補圖方式。

**進度**：實作完成（2026-10-02）
- commit：feat/event-images 32c699f..0eb804c
- 未驗：部落推播次數用完與圖片失敗同時發生時的提示（自動測試沒涵蓋，需實機）
- 實作決定：兩件事合成一則 SnackBar（「活動已建立，…；…」，停 8 秒），圖片失敗附後端原因；照片還在壓縮時按發布會擋下並提示

### T-04 編輯活動時能一起增刪圖片，按儲存才生效

**使用者價值**：發起人在活動開始前改活動資料時，順手就能換海報；跟其他欄位一樣，按返回就什麼都不會改。

**範圍**
- 包含：編輯頁的圖片欄位（顯示既有圖片、標記刪除、新增待上傳）、儲存時依序送出、部分失敗的提示。
- 不包含：詳情頁上的即時增刪（T-01，活動開始後的唯一入口）。

**驗收條件**
- [x] 編輯頁用 T-03 的同一個圖片欄位顯示活動現有圖片，可標記刪除既有圖片、新增圖片，合計不超過 6 張
- [x] 按返回放棄時，圖片與其他欄位都沒有任何改變
- [x] 按儲存後先存文字欄位、再刪除標記的圖片、最後上傳新圖；全部成功顯示「活動已更新」並回到詳情頁，輪播是新的樣子
- [x] 只改圖片、沒改文字時也能儲存
- [x] 文字已存但圖片步驟失敗時，回到詳情頁並提示哪一部分沒更新與後端訊息，引導到詳情頁頂端重試

### T-05 活動卡片有封面時顯示封面

**使用者價值**：瀏覽活動時一眼看出活動內容，有照片的活動更容易吸引人點進去。

**範圍**
- 包含：`EventSummary.coverImageUrl` 解析；精選大卡、廣場小卡以照片取代漸層；`EventList` 的列、`EventStatusTile`、`_EventListItem`（按讚收藏）、`_EventResultTile`（搜尋）右側加小方形縮圖；封面過期換新網址；快取。
- 不包含：詳情頁輪播（T-01、T-02）。

**驗收條件**
- [x] 有封面的活動，在上述六種卡片都顯示封面，裁切填滿不變形
