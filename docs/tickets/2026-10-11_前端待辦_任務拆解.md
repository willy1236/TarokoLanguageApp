## 任務卡

### T-01 參加者收到「活動有更新」推播，點下開活動詳情

**使用者價值**：發起人改了地點、地址或提醒事項，參加者收到推播點一下就能看到新資訊，收件匣紅點也即時更新。

**範圍**
- 包含：`event_updated` 推播的未讀數、前景提示、點擊開詳情。
- 不包含：收件匣列表（現有邏輯已支援）。

**驗收條件**
- [ ] App 在前景收到 `event_updated`：收件匣未讀數更新，跳出本機通知與 SnackBar，標題、內文用推播帶的文字
- [ ] App 在背景或關閉時點 `event_updated` 推播：開啟該活動詳情
- [ ] 前景本機通知點下去同樣開該活動詳情
- [x] `event_id` 缺失或無法解析時不閃退，只記 log（同既有提醒）
- [x] 既有 `event_reminder`、`event_cancelled` 行為不變

**實作設計**
- 後端：推播 `data` 為 `{ type: 'event_updated', event_id }`，標題、內文在 `notification`。
- 前端：`fcm_service.dart` 的 `_inboxPushTypes` 加 `'event_updated'`；`_parseReminderPayload` 的類型判斷加 `event_updated`，前景與點擊兩條路徑（約第 718、952 行）因此自動接上。前景的標題 fallback 目前是「活動提醒」，`event_updated` 一定帶 `notification.title`，不必另訂。檔頭註解（第 6 行附近）的 payload 清單一併補上。

**依賴**：無

**進度**：實作完成，未讀數重抓、前景 SnackBar、點擊開詳情的邏輯有測試；系統通知顯示與背景／關閉時點推播待實機驗證（commit 5baff72、f564e4f、6cb7b67）。實作時決定：詳情頁開著時收到本活動的提醒／取消／更新推播，整頁重抓詳情與提醒紀錄，地點、狀態即時更新

### T-02 參加者在活動開始後看不到「退出活動」

**使用者價值**：活動已開始就不能退出，按鈕不該還在，避免按了才被拒絕。

**範圍**
- 包含：詳情頁停留跨過開始時間的情況。
- 不包含：重新載入後的按鈕狀態（後端 `effective_status` 已處理，現況正確）。

**驗收條件**
- [x] 已報名的參加者打開已開始或已結束的活動，按鈕列不出現「退出活動」（現況，回歸確認）
- [x] 活動開始前打開詳情、停留到 `starts_at` 之後，按鈕列不再顯示「退出活動」，改為「已報名 · 活動進行中」
- [x] 萬一仍送出退出並收到 `409 EVENT_STARTED`，顯示「活動已開始或已結束，不能退出」並重新整理詳情

**實作設計**
- 前端：`event_action_bar.dart` 的 `_buildActionBar` 在 `isJoined` 分支前加判斷：`!isHost && e.startsAt.isBefore(DateTime.now())` 視同 `ongoing`。這只在 build 時判斷，不加計時器；使用者有任何互動或下拉重整都會重建。`event_detail_screen.dart` 的 `_runAction` 收到 `EVENT_STARTED` 時呼叫既有 `_silentRefresh()`（比照 `isRegistrationNotOpen` 的處理）。

**依賴**：無

**風險 / 待決**：若想讓按鈕在開始時間一到就自己消失（使用者完全不動也會變），需在詳情頁加計時器；動手的人可評估是否值得。

**進度**：已完成（commit 90a7b4a、7ac7d9e、6cb7b67）

### T-03 發起人修改活動時知道參加者這次有沒有收到通知

**使用者價值**：同一場活動 24 小時內修改超過 3 次後，參加者不會再收到推播。發起人看到提示，才知道要另外通知參加者，避免參加者照舊地點出發。

**範圍**
- 包含：編輯活動成功後的提示。
- 不包含：建立活動時的部落推播上限提示（既有 `tribeNotifyLimited`，行為不變）。

**驗收條件**
- [x] 發起人修改地點、地址或提醒事項，後端回 `notify_limited: true` 時，成功訊息顯示「活動已更新，今天通知次數已達上限，參加者不會再收到推播」，停留時間同既有部落推播提示（8 秒）
- [x] 沒有 `notify_limited`（含只改其他欄位、`notified: 0`）時，只顯示「活動已更新」
- [x] 沒有任何變更（不送 PATCH）時行為不變
- [x] 建立活動的成功訊息與部落推播提示不變

**實作設計**
- 後端：`PATCH /api/events/:id` 回應 `{ ok: true, notified, notify_limited? }`。
- 前端：
  - `EventService.updateEvent` 改回傳 `Future<({bool notifyLimited})>`，讀 `data['notify_limited'] == true`；沒送 PATCH 時回 false。寫法同 `createEvent` 的 `tribeNotifyLimited`。
  - `event_compose_screen.dart` 送出段（約第 299～315 行）：編輯時接住回傳值，`notices` 加入「今天通知次數已達上限，參加者不會再收到推播」，沿用既有的 `$done，${notices.join('；')}` 與 8 秒 SnackBar。

**依賴**：無

**進度**：已完成（commit c4158b2、6cb7b67）
