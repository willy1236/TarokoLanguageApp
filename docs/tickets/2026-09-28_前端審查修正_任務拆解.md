## 任務卡

### T-01 登出或被登出後，這台手機不再收到舊帳號的訊息與推播

**使用者價值**：同一台手機換帳號時，B 看不到 A 的私訊，也不再收到 A 的推播（私訊預覽、好友邀請、論壇回覆）。

**範圍**
- 包含：登出關閉聊天連線（A1）、強制登出與啟動時到期登出都刪除本機 FCM token（A3）、登出先刪 JWT（B5）。
- 不包含：JWT 到期自動續期（T-09）。

**驗收條件**
- [ ] A 進過好友列表後登出、B 登入並進好友列表：A 的好友傳訊息給 A 時，B 的畫面不出現；B 自己收到的新訊息即時出現。
- [ ] 任一 API 回 401 被強制登出後，舊帳號收到私訊或好友邀請時，這台手機不再跳推播。
- [ ] 啟動時 JWT 已過期被導回登入頁，舊帳號的推播同樣不再出現。
- [ ] Google 或 Firebase 登出丟例外時，重開 App 仍是登出狀態。
- [ ] 一般登出仍會向後端註銷裝置（`device_tokens` 移除本機 token）。
- [ ] `ChatController.disconnect()` 後重設重連次數與 `lastEvent` 的單元測試。

**實作設計**
- 前端：
  - `SessionService.signOut`：開頭呼叫 `chatController.disconnect()`；`unregisterDevice: false` 時改呼叫新的 `FcmService.deleteLocalToken()`（只做 `_fm.deleteToken()` 與清 `_lastToken`，以 `PlatformFeatures.supportsPush` 守門），`unregisterDevice()` 內部也改用它。
  - `ChatController.disconnect()`：另外重設 `_reconnectAttempts`、`_refreshedForExpiry`、`lastEvent`，`_reconnectTimer` 設為 null。`_sub` 先取消，`sink.close()` 不會再進 `_onClosed` 觸發重連。
  - `AuthService.signOut`：先刪 `session_token`、`session_expires_at`，再登出 Google 與 Firebase，兩步各自 try。
  - 新增 `SessionService.restore()`：token 有效回 true；過期就走 `signOut(unregisterDevice: false)` 後回 false。`splash_screen.dart` 改呼叫它。`AuthService.isLoggedIn` 改為純查詢，不再帶登出副作用，`_uploadIfLoggedIn` 因此不會在 App 使用中靜默登出。
  - `FcmService` 的 `getToken` 移進 try。登出順序與續期成功的測試在 `test/services/session_service_test.dart`。

**依賴**：無

**進度**：完成（2026-09-28）
- commit：#95（`9e9e96f`）
- 未驗：A 帳號登出、B 帳號登入後，A 的私訊與推播不再出現；401 被強制登出、JWT 過期被導回登入頁之後，都不再收到舊帳號的推播。

**使用者價值**：對方掛斷或在通話中封鎖後，留下的一方不會獨自待在空房間等倒數結束。

**範圍**
- 包含：處理 `friend_call_ended` 推播的前景與點擊通知兩條路徑。
- 不包含：隨機配對的 `video_session_ended`（既有，不變）。

**驗收條件**
- [ ] 好友通話中 A 掛斷，B 在推播到達後離開通話畫面，流程與隨機配對時對方掛斷相同。
- [ ] A 在通話中封鎖 B，結果同上。
- [ ] B 的 App 在背景時點「通話已結束」通知，回到 App 後通話已結束。
- [ ] 收到的 `call_id` 不是目前這通（舊通話的延遲推播）時，目前的通話不受影響。
- [ ] B 結束時不會再呼叫 `POST /api/friends/calls/:id/end`。

### T-04 網路中斷恢復後，聊天自動補齊漏掉的訊息

**使用者價值**：網路閃斷或切背景回來後，不用重進聊天室就看得到期間的訊息；長時間離線也不會零間隔狂連、耗電。

**範圍**
- 包含：重連間隔夾住指數（A4）、`connected` 後重抓（B1）。

**驗收條件**
- [ ] 聊天室開著時斷網 1 分鐘、期間對方傳 3 則，網路恢復後這 3 則自動出現。
- [ ] 好友列表開著時同樣操作，對話列表的最後一則與未讀數更新。
- [ ] 往上捲看舊訊息時剛好重連，已載入的舊訊息不被清掉。
- [ ] 離線期間的新訊息超過一頁（30 則）時，新舊兩段接不起來，改為整頁替換成最新一頁，已載入的舊訊息要重新往上捲；這樣畫面上不會出現看不到的缺口。
- [ ] 單元測試：重連次數 5、63、100 時，間隔都是 30 秒。
- [ ] 後端部署時以 close code `1001` 斷線，聊天會重連並補齊訊息（與 `1006` 相同）。
- [ ] 好友列表與聊天室第一次 `connected` 也會補抓；初次載入途中就連上時，等載入完成再補抓。

**實作設計**
- 前端：
  - `chat_socket_service.dart`：`_scheduleReconnect` 改為 `min(30, 1 << min(_reconnectAttempts, 5))`，計算抽成 `@visibleForTesting` 的純函式。
  - `chat_screen.dart`：`_onChatEvent` 收到 `connected` 時重抓最新一頁，以 message id 合併進 `_messages`（不同於 `_load()` 的整頁替換，也不動 `_nextCursor`）。
  - `friends_list_screen.dart`：收到 `connected` 時呼叫 `_loadConversations()`。

**依賴**：無

**進度**：完成（2026-09-28）
- commit：#95（`9e9e96f`）
