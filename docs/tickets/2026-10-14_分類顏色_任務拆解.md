- 既有相關機制：

  - `lib/services/category_service.dart` 依模組快取分類清單；`labelOf` 是同步查表（快取 → 預設對照 → value）。活動頁 `events_screen.dart` 的 `_loadCategories` 每次都 `refresh: true` 重抓並 `setState`，列表跟著重繪。

  - 後台分類管理 `lib/screens/admin/admin_categories_screen.dart`：文章／影音／活動三個分頁，`_CategoryDialog` 負責新增與編輯（名稱、排序），編輯時只送有變的欄位；成功後 `_load` 會 `CategoryService.fetch(m, refresh: true)`，使用者端快取一併更新。API 呼叫在 `AdminService.createCategory`／`updateCategory`（`lib/services/admin_service.dart`）。
- 這次會動到的既有部位：`content_category.dart`、`category_service.dart`、`event_cards.dart`、`admin_service.dart`、`admin_categories_screen.dart`。
- 已定案的技術前提：

  - 預設分類的後端顏色與現行 `_categoryColor` 對照相同，改完後畫面應無差異。
  - 只有活動分類能設顏色；文章、影音帶 `color` 後端回 400。PATCH 帶 `color: null` 為清除，不帶為不變。
  - 管理員發活動時自動加入的新分類 `color` 為 `null`。
  - 後台選色（2026-10-14 拍板）：六個色票 `primary`、`primaryDeep`、`moss`、`mossDeep`、`goldDeep`、`inkSoft`，加上自由輸入 `#RRGGBB`。
  - 後端實作（`backend/categories.ts` 的 `normalizeCategoryColor`、`backend/routes/admin-categories.ts` 的 `parseColor`，migration 075）：送出時大小寫都收、存成大寫；資料表有 `CHECK (color ~ '^#[0-9A-F]{6}$')`，回傳的 `color` 一定是大寫 `#RRGGBB` 或 `null`。後端不限色票，任何 `#RRGGBB` 都收。PATCH 只帶 `color` 也可以；三個欄位都沒帶回 400。

## 任務卡

### T-01 [共用] `ContentCategory` 解析 `color`

**使用者價值**：T-02（卡片讀顏色）與 T-03（後台顯示、編輯顏色）讀同一個欄位，先定好模型，兩張卡可以並行。

**範圍**
- 包含：`color` 欄位與解析、轉成 `Color` 的 getter。
- 不包含：依分類查顏色（T-02）、色票清單（T-03）。

**驗收條件**
- [ ] `color` 為 `"#7A1F1A"` 時解析成該字串，`displayColor` 為 `Color(0xFF7A1F1A)`
- [ ] `color` 為 `null`、缺欄位時 `displayColor` 為 null；格式不是 `#RRGGBB`（如 `"red"`、`"#FFF"`，後端有 CHECK 不會回，屬防禦）時也回 null，不閃退、不讓整份清單失敗
- [ ] 文章、影音清單沒有 `color` 欄位，解析結果不變
- [ ] 單元測試涵蓋上述情況

**實作設計**
- 前端：`lib/models/content_category.dart`
- 介面：
  ```
  class ContentCategory {
    ...
    /// 後端存的 `#RRGGBB`（大寫）；null＝用 App 預設色。只有活動分類會有值。
    final String? color;
    /// [color] 轉成 Color；null 或格式不對回 null。
    Color? get displayColor;
  }
  ```
  `color` 保留原字串（後台編輯時比對、回送用），格式不對時 `color` 仍保留原值、`displayColor` 回 null。

**依賴**：無

**進度**：未完成

### T-02 活動卡片日期方塊照後端設定的分類顏色顯示

**使用者價值**：管理員在後台幫分類設了顏色，使用者在活動列表就看到對應的日期方塊顏色；新分類也能有自己的顏色，不再一律是 `inkSoft`。

**範圍**
- 包含：活動列表一般列的日期方塊與分類標籤底色。
- 不包含：後台選色（T-03）。

**驗收條件**
- [ ] 活動分類清單抓回來後，分類有 `color` 時日期方塊底色、分類標籤底色用該顏色
- [ ] 清單還沒抓回來、抓取失敗、或該分類 `color` 為 null 時，沿用原本的寫死對照與預設 `inkSoft`
- [ ] 後端預設分類（走讀、線上、工藝、族語、音樂、其他）顯示與改動前完全相同（回歸）
- [ ] 下拉重新整理後，後台剛改過的顏色會反映在列表上
- [ ] widget 測試：快取有顏色時用快取色、沒有時用寫死對照

**實作設計**
- 前端：
  - `category_service.dart` 新增同步查詢 `static Color? colorOf(CategoryModule m, String value)`，比照 `labelOf` 只查快取、查不到回 null；不放預設對照（預設對照屬於活動卡片的視覺，留在 `event_cards.dart`）。
  - `event_cards.dart` 的 `_categoryColor`：先 `CategoryService.colorOf(CategoryModule.events, category)`，null 再走原 switch。`category` 為 null 時直接走 switch 的 default。
  - 重繪時機沿用既有機制：`events_screen.dart` 的 `_loadCategories` 抓完會 `setState`，卡片跟著重建，不需另加監聽。

**依賴**：T-01

**風險 / 待決**：管理員可能經由 API 直接設任意顏色（不經後台色票），日期方塊上的金色、米白文字可能看不清；這張卡不擋，照後端值顯示。

**進度**：未完成

### T-03 管理員能在後台幫活動分類選顏色、清除顏色

**使用者價值**：管理員新增分類（含發活動時自動加入的分類）後，能在分類管理幫它挑一個 App 的顏色或自己輸入色碼，活動列表上就能一眼區分；不需要再請工程師改程式。

**範圍**
- 包含：活動分頁的新增／編輯對話框選色、輸入色碼與清除、列表列顯示目前顏色、`AdminService` 送出 `color`。
- 不包含：文章、影音分頁（不顯示選色、不送 `color`）。

**驗收條件**
- [ ] 活動分頁的新增、編輯對話框有六個色票（`primary`、`primaryDeep`、`moss`、`mossDeep`、`goldDeep`、`inkSoft`）、「不指定（用預設色）」與色碼輸入欄；文章、影音分頁的對話框沒有選色
- [ ] 色票以實際顏色的圓點顯示，選中的有明顯標記；預覽能看出日期方塊上的金色、米白文字在該底色上的樣子
- [ ] 點色票時色碼欄同步顯示該色碼；在色碼欄輸入的值剛好是某個色票時，該色票顯示為選中
- [ ] 色碼欄輸入 `#RRGGBB`（大小寫皆可）即時更新預覽；格式不對時顯示錯誤、不能送出
- [ ] 新增時選了顏色，`POST` 帶 `color`；選「不指定」則不帶
- [ ] 編輯時改顏色，`PATCH` 只帶 `color`（加上其他有變的欄位）；改成「不指定」送 `color: null`；顏色沒變不送 `color`；名稱、排序、顏色都沒變直接關閉
- [ ] 編輯時分類現有顏色不在色票裡，色碼欄帶出該值、沒有色票選中；沒動它就不送 `color`，不會被意外清掉
- [ ] 活動分頁的列表列顯示目前顏色的小色塊，`null` 顯示預設色並標示「預設」
- [ ] 儲存成功後回到活動列表，日期方塊顏色已更新（依賴 T-02 驗收）

**實作設計**
- 前端：
  - `admin_service.dart`：`createCategory` 加 `String? color`（null 不帶）；`updateCategory` 需要區分「不變」與「清除」，加一個參數表達三種狀態（例如 `String? color` 搭配 `bool clearColor`，或包一層 `Optional`），實作者擇一，註解寫明。
  - `admin_categories_screen.dart`：
    - 色票清單定義在本檔（只有這裡用），每筆存 `AppColors` 常數與對應的 `#RRGGBB` 大寫字串；比對一律轉大寫。
    - `_CategoryDialog` 依 `module == CategoryModule.events` 顯示選色列與色碼 `TextField`；狀態只有一個「目前的 hex（大寫）或 null」，色票與輸入欄都讀寫它，送出前與 `editing.color` 比對決定送不送。色碼格式檢查可沿用 T-01 的解析（`displayColor` 為 null 即格式錯）。
    - `_row` 在活動分頁顯示色塊。

**依賴**：T-01

**進度**：未完成
