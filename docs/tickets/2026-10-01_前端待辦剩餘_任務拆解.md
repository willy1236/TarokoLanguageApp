## 現況與前提

- 技術棧：Flutter（Android／iOS 為主，Web 版另外處理），Agora RTC（`agora_rtc_engine` 6.5.2），即時連線用 `web_socket_channel`，頭像裁切用 `crop_your_image` 2.0.0。
- 既有相關機制：
  - 通話結束只靠推播：`FcmService.onVideoSessionEnded`（隨機配對）、`FcmService.onFriendCallEnded`（好友通話），由 `VideoCallScreen` 在 initState／dispose 掛上與清空，前景與點擊通知兩條路徑分別在 `_onForegroundMessage`、`_handleOpened` 解析。
  - 即時連線 `ChatController`（`chat_socket_service.dart`）只認 `connected`／`message`／`read`，其餘 `type` 丟掉；只有聊天室與好友列表會呼叫 `chatController.connect()`，連上後一直保持到登出。
  - Agora `onUserOffline` 在 `agora_video_rtc.dart` 轉成 `RtcCallbacks.onRemoteLeft(uid)`，沒有帶 reason；`VideoCallController` 只清掉 `_remoteUid`。
  - 撥出等待畫面、來電畫面每 2 秒輪詢通話狀態。
  - 頭像：`profile_screen.dart` `_pickAndUploadAvatar` 以原圖進 `AvatarCropScreen`，裁切輸出原解析度 PNG，再檢查 8MB；Web 版走 `_uploadAvatarWithoutFileSystem`，流程相同。
- 版本：`pubspec.yaml` 為 `1.0.0+12`，`remoteconfig.template.json` 的 `latest_version_*` 為 `1.0.0+12`、`min_version_*` 為 `1.0.0+11`。Android 的 versionCode 取自 pubspec；iOS 的 `ios-testflight` workflow 以 `--build-number=$BUILD_NUMBER` 覆寫成 Codemagic 建置序號，TestFlight 上的 build 號因此比 pubspec 多約兩號。Remote Config 範本合進 master 後由 `deploy-remote-config.yml` 比對差異、等核准才發布。
- 這次會動到的既有部位：`lib/services/chat_socket_service.dart`、`lib/services/fcm_service.dart`、`lib/screens/community/video_call/`（`video_rtc.dart`、`agora_video_rtc.dart`、`video_call_controller.dart`）、`lib/screens/community/video_call_screen.dart`、`lib/screens/friends/directed_call_waiting_screen.dart`、`lib/screens/friends/incoming_call_screen.dart`、`lib/screens/chat/chat_screen.dart`、`lib/screens/profile/avatar_crop_screen.dart`、`lib/screens/profile/profile_screen.dart`、`pubspec.yaml`、`codemagic.yaml`、`remoteconfig.template.json`。
- 已定案的技術前提：
  - 後端通話事件經 WebSocket 與推播同時送出、內容相同、id 一律字串；前端要冪等處理（`API/即時連線.md`「通話事件」）。
  - 對方斷線（dropped）等約 15 秒再查狀態。
  - 後端 `POST /api/me/avatar` 介面不變、8MB 上限不放寬，後端會縮成 512×512 WebP。
  - `NEED_FRIEND` 的兩種原因後端訊息都已寫好，前端不推測、不顯示對方年齡。

## 任務卡

### T-01 通話中對方掛斷時，沒收到推播也會立即退出

**使用者價值**：關掉通知權限、推播延遲或按過「登出所有裝置」的人，對方掛斷後不會停在空白通話畫面等 30 分鐘倒數結束。

**範圍**
- 包含：即時連線解析七種通話事件，走跟推播同一套處理；推播與即時連線重複收到同一事件只處理一次；撥出等待、來電畫面收到事件時立即查狀態。
- 不包含：Agora 回報對方離開頻道的處理（T-02）。

**驗收條件**
- [ ] 隨機配對通話中，對方掛斷，只收到即時連線的 `video_session_ended`（推播關閉）也會退出通話畫面
- [ ] 好友通話中，對方掛斷，只收到即時連線的 `friend_call_ended` 也會退出
- [x] 推播和即時連線都收到同一則 `friend_call_ended`／`video_session_ended`，只退出一次、不會導頁兩次
- [x] 即時連線收到 `friend_call_incoming` 只開一個來電畫面，之後再收到同 `call_id` 的推播不會再開一次
- [ ] 撥出等待中對方接聽或拒接，收到 `friend_call_accepted`／`friend_call_declined` 後不必等下一輪輪詢就切換畫面
- [ ] 響鈴中對方取消，即時連線的 `friend_call_cancelled` 會關掉來電畫面
- [ ] 從沒開過好友列表或聊天室，直接進隨機配對通話，對方掛斷時即時連線也收得到（進配對等待畫面就會連上）

**實作設計**
- 前端：
  - `ChatSocketEvent` 新增 `call` 類型，攜帶原始 `data`（`Map<String, String>`）；`fromJson` 對上表七種 `type` 回傳 `call` 事件。
  - `FcmService` 把通話類推播的前景處理（`video_matched`、`video_session_ended`、`friend_call_*`）抽成一個公開入口，例如 `FcmService.handleCallEvent(Map data, {required bool fromSocket})`；前景推播與即時連線都呼叫它。入口內以 `type + call_id/session_id` 做去重（保留最近數十筆），處理過就略過。`_handleOpened`（點通知）也經同一份去重記錄，避免先收到即時連線、又點通知時重複導頁。
  - 即時連線來的事件不彈本地通知（使用者 App 開著，前景推播的 fallback 通知會照舊由推播那條負責；兩條都到時第二條被去重）。
  - 新增 `onFriendCallAccepted`／`onFriendCallDeclined` 回呼，由 `DirectedCallWaitingScreen` 掛上，收到就立即 `_poll()`；不直接用 payload 導頁。
  - `ChatController` 的監聽者目前只有聊天室與好友列表；通話事件改由一個全域監聽者（`main.dart` 啟動時掛一次）轉給 `FcmService.handleCallEvent`，不依賴哪個畫面開著。
  - 即時連線在進入通話相關畫面（`VideoWaitingScreen`、`DirectedCallWaitingScreen`、`IncomingCallScreen`、`VideoCallScreen`）的 initState 呼叫 `chatController.connect()`（已連上時不做事），之後照舊保持到登出。沒進過這些畫面時，App 開著收好友來電仍只靠推播。

**依賴**：無

**風險 / 待決**：`lastEvent` 是單一欄位＋`notifyListeners`，短時間內連續兩則事件監聽者可能只讀到後一則；通話事件若走同一個 `lastEvent` 會漏，建議通話事件另開 `Stream` 或直接在 `_onData` 呼叫全域 handler。

**進度**：實作完成（2026-10-01）
- commit：95af5ca、e533920、65226f6、59e861e
- 未驗：只收到即時連線時隨機配對／好友通話退出、撥出等待收到接聽／拒接立即切換、響鈴中對方取消關閉來電畫面、沒開過好友列表直接進配對也收得到（需兩台裝置、關閉通知權限實測）

### T-02 對方離開視訊頻道時，確認通話已結束就自己退出

**使用者價值**：推播與即時連線都沒到（例如兩邊都斷線）時，對方主動離開頻道也能讓這邊退出，不會卡在空白畫面。

**範圍**
- 包含：區分 Agora 回報的「對方主動離開」與「對方斷線」，查後端通話狀態，已結束就本地退出（不再通知後端）。
- 不包含：即時連線事件（T-01）。

**驗收條件**
- [ ] 好友通話中對方按掛斷，Agora 回報主動離開後查 `GET /api/friends/calls/:id`，狀態已結束就退出
- [ ] 隨機配對通話中對方按掛斷，查 `GET /api/video/session/current`，目前的 session 不是這一通（或為 null）就退出
- [x] 對方網路斷線，15 秒內回到頻道，通話照常繼續、不查狀態
- [x] 對方網路斷線超過 15 秒沒回來，查一次狀態；後端仍顯示通話中就留在畫面等倒數或手動掛斷
- [x] 查狀態失敗（網路錯誤）不退出、不跳錯誤
- [x] 查狀態途中或之後推播已讓通話結束，不會重複退出

**實作設計**
- 前端：
  - `video_rtc.dart`：`onRemoteLeft` 改為 `void Function(int uid, RemoteLeftReason reason)`，新增 `enum RemoteLeftReason { quit, dropped, other }`；`agora_video_rtc.dart` 把 `UserOfflineReasonType.userOfflineQuit`／`userOfflineDropped` 對應過去，其餘為 `other`。
  - `VideoCallController` 建構子多注入 `Future<bool> Function() isEndedOnServer`：`quit` 立即查、`dropped` 開 15 秒計時器（`onRemoteJoined` 時取消），到時查；回 true 就 `_leave(notifyBackend: false)`。`other`（例如轉為觀眾）只清畫面。計時器在 `_leave`、`dispose` 取消。
  - `VideoCallScreen` 提供 `isEndedOnServer`：好友通話 `DirectedCallService.getCall(id)` 的 `status` 不是 `accepted` 視為已結束；隨機配對 `VideoCallService.fetchCurrentSession()` 的 `session?.id != widget.session.id` 視為已結束。例外一律回 false。
  - controller 已有注入時鐘與假 `VideoRtc`，可用既有測試方式驗 quit／dropped／回來／查失敗四種情境。

**依賴**：無

**風險 / 待決**：好友通話 `status` 在「已接通、進行中」時是否固定為 `accepted` 要對照後端 `API/好友.md` 確認；若有其他進行中狀態值要一併列入。

**進度**：實作完成（2026-10-01）
- commit：127820e、8fcc531、3ba9ce9
- 未驗：好友通話與隨機配對中對方按掛斷，實際查後端狀態後退出（需兩台裝置、關閉通知權限並斷開即時連線實測）

### T-04 大張照片也能換頭像

**使用者價值**：用手機相機原圖（約 4000×3000）換頭像，不會被「檔案大小不可超過 8MB」擋下。

**範圍**
- 包含：選圖時先縮小、裁切後再縮成固定尺寸輸出；手機與 Web 兩條上傳路徑。
- 不包含：GIF（跳過裁切直接上傳，行為不變）。

**驗收條件**
- [ ] 用 4000×3000 以上的相機原圖換頭像，裁切後上傳成功
- [x] 上傳的檔案邊長不超過 1024
- [ ] 直拍照片裁切後方向正確（沿用既有 EXIF 轉正）
- [ ] 8MB 以上的 GIF 仍顯示「檔案大小不可超過 8MB」
- [ ] Web 版同樣流程上傳成功

**實作設計**
- 前端：
  - `pubspec.yaml` 把 `image`（目前是 `crop_your_image` 的間接依賴）加成直接依賴。
  - `pickImage` 不帶 `maxWidth`／`maxHeight`／`imageQuality`：Android 的 `image_picker` 帶這些參數時會把 GIF 解成單張重存成 JPEG，動畫消失、8MB 以上的 GIF 也不再被擋；選圖前又無法得知是不是 GIF。代價是裁切與 T-05 旋轉要處理原尺寸大圖，比較慢。
  - 裁切結果統一經一個小函式縮到邊長 1024（已小於就不動），輸出 PNG；兩條上傳路徑都呼叫它，放在 `avatar_crop_screen.dart` 內、`Navigator.pop` 前處理，呼叫端不必知道。解碼與縮放用 `compute` 移出 UI thread，Web 上 `compute` 會退回主執行緒，照樣可用。

**依賴**：無

**風險 / 待決**：輸出 PNG 或 JPEG 由實作決定；1024×1024 照片 PNG 約 1-2MB，離 8MB 很遠。

**進度**：實作完成（2026-10-01）
- commit：ab55cea
- 未驗：4000×3000 以上相機原圖上傳成功、直拍方向正確、8MB 以上 GIF 仍被擋、Web 版上傳（需裝置與瀏覽器）

- [ ] 旋轉後裁切，上傳的頭像方向與畫面上看到的一致
