# 2026-10-12 前端待辦（好友聊天室：訊息時間、已讀、通話紀錄）任務拆解

來源：後端 repo `說明文件/前端交接/2026-10-12_前端待辦.md`（決策紀錄 A50，規格 `docs/superpowers/specs/2026-10-12-chat-call-log-design.md`）。

## 現況與前提

- 技術棧：Flutter（`lib/`），後端已上線（主服務 `00243-jay`，migration 070），本次只動前端。
- 既有相關機制：
  - 聊天室 `lib/screens/chat/chat_screen.dart`：`_messages` 新到舊、`ListView(reverse: true)`；`_bubble` 只畫內文，自己**最後一則**（`isLastMine`）在泡泡內底下顯示「已讀／已送出」。`_load` 整頁替換、`_catchUp` 重連後用 `mergeLatestMessages`（`lib/models/friend_message_model.dart`）併最新一頁、`_loadMore` 依 `_nextCursor` 往上分頁；`_refreshFromPush` 供私訊推播重載。右上角視訊鈕走 `_startVideoCall`（唯讀帳號、對方無法使用、平台不支援時擋下）。
  - 「聊天列表」其實是好友分頁 `lib/screens/friends/friends_list_screen.dart`：列表本體是 `GET /api/friends`（後端依成為好友時間新到舊），`GET /api/friends/messages` 只拿來當 `_conversationsByCode` 查表，補最後一則預覽與未讀數；**後端對話排序目前沒被用到**。對象無法使用的好友只有 `lastMessage != null` 才能點進聊天室看歷史。
  - 通話事件：`friend_call_*` 同時走推播與即時連線，兩邊都進 `FcmService._handleCallEvent`（`lib/services/fcm_service.dart`）去重後分派給各畫面的靜態回呼。除了 `friend_call_incoming` 帶 `caller_friend_code`，其餘只帶 `call_id`，**看不出是哪位好友**。
  - `FriendService.markRead` 只在 `marked > 0` 時重抓紅點；只清掉未接來電（`calls_marked > 0`、`marked == 0`）時紅點不會更新。
  - 日期格式集中在 `lib/core/utils/date_format.dart`（先 `toLocal()` 再格式化），既有 `weekdayLabel` 是「週四」形式。
  - App 沒有 `RouteObserver`。
- 這次會動到的既有部位：`chat_screen.dart`、`friend_message_model.dart`、`friend_service.dart`、`date_format.dart`、`friends_list_screen.dart`、`fcm_service.dart`、`chat_socket_service.dart`、`directed_call_waiting_screen.dart`、`main.dart`。
- 已定案的技術前提：
  - 後端只新增欄位，舊版 App 不會壞；`kind` 由後端依「誰在看」算好，前端只照著顯示，不自己推斷是否拒接。
  - 交接文件 B 段（拒接後 60 秒內回撥直接接通、響鈴逾時回 `missed`、紅點含未接來電）現有撥號／來電畫面不用改。
  - 時間顯示沿用 App 慣例：`date_format.dart` 的 `toLocal()`，台灣使用者即台灣時間。

## 任務卡

### T-01 [共用] 通話紀錄模型：解析 `calls`／`last_call`

**使用者價值**：T-03（聊天室 `calls`）與 T-05（聊天列表 `last_call`）讀同一種格式，先定好模型，兩張卡可以並行，不會各寫一份解析。

**範圍**
- 包含：`FriendCall` 類別與 `fromJson`。
- 不包含：顯示文字與泡泡（T-03）、列表預覽文字（T-05），兩處的文字不同，不放進模型。

**驗收條件**
- [x] 四種 `kind`（`completed`／`cancelled`／`missed`／`declined`）解析成對應列舉值；不認得的字串不閃退（解析成「其他」或回 null，由實作者決定，T-03／T-05 照此略過不顯示）
- [x] `duration_sec` 為 `null` 或缺欄位時為 null；`is_unread` 缺欄位時為 false
- [x] `id` 為字串或數字都能解析（比照 `FriendMessage._toInt`）
- [x] 單元測試涵蓋上述情況

**實作設計**
- 前端：`lib/models/friend_message_model.dart` 新增（與 `FriendMessage` 同檔，同屬 `friendMessages.ts` 的回應）。
- 介面：
  ```
  enum FriendCallKind { completed, cancelled, missed, declined }
  class FriendCall {
    final int id;
    final FriendCallKind kind;
    final bool mine;          // 我是撥出方 → 泡泡靠右
    final DateTime createdAt; // 撥出時間，與訊息一起排序
    final int? durationSec;   // 只有 completed 有值
    final bool isUnread;      // 只有 missed 可能為 true
    factory FriendCall.fromJson(Map<String, dynamic> j);
  }
  ```
  `fromJson` 遇到未知 `kind` 的行為由實作者定，但要寫進類別註解，T-03／T-05 依此過濾。

**依賴**：無

**進度**：完成（2026-10-13）
- commit：a8bf9b3、da5875d
- fixture：沒有重錄 `get_api_friend_messages.json`／`get_api_friends_messages.json`（錄製要在模擬器點帳號），格式依後端 `backend/callLog.ts` 的 `chatCallJson` 對照
- 審查：兩輪獨立審查，無未處理的 blocking

**實作時決定**
- `FriendCall.fromJson` 是回傳 `FriendCall?` 的 static 方法：`kind` 不認得或 `created_at` 解析不了回 null，呼叫端略過；另有 `FriendCall.listFromJson` 解析 `calls` 陣列並略過 null

### T-03 使用者在聊天室看得到通話紀錄，點一下回撥

**使用者價值**：打過、接過、錯過的視訊通話留在聊天室裡，錯過的電話事後也知道，點一下就能回撥。

**範圍**
- 包含：`calls` 的取得、與訊息依時間合併、分頁、通話泡泡、點擊回撥、進聊天室清掉未接來電的紅點。
- 不包含：聊天室開著時通話剛結束的即時出現（T-04）、好友列表的通話預覽（T-05）。

**驗收條件**
- [x] 通話與訊息依 `created_at` 混排；通話泡泡依 `mine` 放撥出方那一側，旁邊有時間，跨日分隔同 T-02
- [x] 文字：`completed`「視訊通話 05:32」（`duration_sec` 轉 分:秒，滿 1 小時為 時:分:秒）、`cancelled`「已取消」、`missed`「未接視訊通話」紅字、`declined`「已拒接」，各附視訊圖示
- [x] 點通話泡泡＝回撥，走右上角視訊鈕同一個流程（唯讀帳號、對方無法使用、平台不支援時一樣擋下並提示）
- [x] 往上捲載入更舊的一頁時，該頁的 `calls` 一起併入，不重複、不漏；只有通話沒有訊息的對話也能顯示，不出現「還沒有訊息」空狀態
- [x] 重連補抓（`_catchUp`）時，同一通以新抓到的為準（例如未讀狀態變了），不重複
- [x] 進聊天室後只有未接來電被清掉（`marked == 0`、`calls_marked > 0`）時，底部分頁的紅點也會更新
- [x] 長按通話泡泡不跳檢舉（檢舉只針對訊息）

**實作設計**

  - `friend_message_model.dart`：可比照 `mergeLatestMessages` 加通話的合併函式並補單元測試（`test/models/friend_message_merge_test.dart`）。

**使用者價值**：在好友分頁一眼看出跟誰最近聊過、誰打來沒接到，未接來電也算進未讀數。

**驗收條件**

- [x] 最後活動是通話時，預覽顯示「[視訊通話]」；是未接來電（`kind == missed`）時顯示「未接視訊通話」紅字；是訊息時照舊（自己的加「你：」）

- [ ] 有新訊息或通話後重抓對話資料，列表順序跟著更新
- [x] 帳號無法使用的好友，只有通話紀錄、沒有訊息時，仍可點進聊天室看紀錄
- [x] 舊回應沒有 `last_call`／`last_activity_at` 時不閃退，退回用 `last_message.created_at`

**實作設計**

### T-04 聊天室開著時，剛結束或未接的通話立即出現，紅點跟著更新

**使用者價值**：在聊天室裡講完電話、或對方打來沒接到，回到聊天室就看到那通紀錄，不用退出再進來；好友列表與紅點也同步。

**範圍**
- 包含：聊天室回到最上層時補抓、收到 `friend_call_*` 時重抓開著的聊天室、好友列表與紅點。
- 不包含：通話泡泡本身（T-03）。

**驗收條件**
- [ ] 從聊天室撥出，不論接通後誰掛斷、對方沒接、自己取消，回到聊天室時那通已出現
- [ ] 在聊天室時對方打來，不論接聽後誰掛斷、拒接、沒接，來電／通話畫面關掉回到聊天室時那通已出現；未接的不留未讀（已在聊天室內，隨即清掉）
