# 2026-09-29 指定其他使用者改用好友碼 任務拆解

來源：`Truku_backend/說明文件/前端交接/2026-09-28_加急_API格式統一.md` §3.2（SCAN-S02，2026-09-29 改版，決策紀錄 A28），即 `2026-09-29_前端待辦.md` A5。規格：`API/00_核心與認證.md` §0「識別其他使用者」、`API/好友模組.md`、`API/即時連線.md`。後端已上線 `00182-dip`（過渡期：uid 與好友碼都收、回應兩種都帶）。

## 現況與前提
- 技術棧：Flutter，所有請求走 `ApiClient`；路徑集中在 `ApiConfig`（`lib/core/constants/api.dart`）。
- 既有相關機制：
  - `ApiConfig` 的好友路徑（`friendRequestAccept`／`Decline`、`friendDetail`、`friendBlockDetail`、`friendShowcase`、`friendCall`、`friendMessages*`）全部收 `int uid`；`FriendService` 各方法同樣以 uid 為參數，`sendRequest` 已支援 `friendCode` 或 `uid` 擇一，`blockUser` 送 `{uid}`。
  - Model 讀他人 uid：`friend_model.dart`（`uid`、`callerUid`、`peerUid`）、`friend_message_model.dart`（`senderUid`、`recipientUid`、`partnerUid`）、`public_profile_model.dart`（`uid`、精選好友 `uid`）、`forum_models.dart`（作者 `uid`），缺欄位時變 0；`video_call_model.dart:34` `peer_uid`、`event_model.dart:121` `host_uid`、`:346` 名單 `uid` 用 `!` 強制非空，開關開啟後會丟例外、整頁打不開。
  - 已有 `friend_code` 的 model：好友／邀請／封鎖、私訊、論壇作者與通知 actor、好友來電 `callerFriendCode`、公開個人頁。
  - 聊天室 `ChatScreen` 以 `partnerUid` 辨識（`routeNameFor(uid)`），以 `sender_uid == 我` 判斷訊息方向；`ChatSocketService` 讀 `message.sender_uid`、`read.by_uid`。
  - 推播：`FcmService._parseFriendPush` 讀 `from_uid`／`uid`，交給 `friend_push_navigation.dart` 的 `openFriendPush` 以 `FriendService.findFriend(uid)` 找好友。
  - `FramedUserAvatar`（`lib/shared/widgets/user_avatar.dart`）以 `userUid == UserService.currentUid` 判斷是不是自己。
  - 視訊：`video_call_controller.dart` 以 API 回的 `uid` 加入 Agora 頻道；`video_call_screen.dart:162` 通話中封鎖傳 `peerUid`。
- 這次會動到的既有部位：`lib/core/constants/api.dart`；`lib/models/` 的 friend_model、friend_message_model、public_profile_model、forum_models、video_call_model、event_model；`lib/services/` 的 friend_service、directed_call_service、chat_socket_service、fcm_service；`lib/screens/friends/`（friends_list、friend_requests、blocked_users、public_profile、directed_call_waiting、friend_push_navigation）、`lib/screens/chat/chat_screen.dart`、`lib/screens/community/video_call_screen.dart`、`lib/screens/events/`（event_detail_screen、widgets/event_detail_body、widgets/event_action_bar）、`lib/screens/forum/`、`lib/shared/widgets/user_avatar.dart`、`lib/main.dart`；`test/fixtures/api/`。
- 已定案的技術前提：
  - App 指定其他使用者一律用好友碼；自己的 uid（`/api/me`、登入回應）不受影響，但判斷「是不是我」改用 `mine`／`is_host`／`is_caller` 或比對自己的 `friend_code`。
  - Agora 加入頻道一律用 API 回的 `uid`（或 `agora_uid`），不改用帳號 uid。
  - 驗收以後端新版格式為準：測試資料依規格文件的回應範例（開關開啟後的格式，不含他人 uid），程式符合新版格式即可放行，不另外驗證開關開啟後的實際行為。
  - 收到 `400 FRIEND_CODE_REQUIRED` 顯示後端 `message`。
- 收尾（不開卡）：全部卡完成 → 照升版本三件事（pubspec、Remote Config 範本、release AAB）上架 → Remote Config 最低版本提高到新版 → 通知後端開啟 `FRIEND_CODE_ENFORCE`。開啟前需先解決 `2026-09-29_管理員後台_任務拆解.md` 待決 1，否則後台角色設定會失效。

## 任務卡

### T-01 使用者以好友碼送出、接受、拒絕好友邀請

**使用者價值**：後端開啟好友碼強制後，加好友流程照常可用，也不再能被人拿遞增的 uid 亂送邀請。

**範圍**
- 包含：`ApiConfig` 好友路徑參數改為好友碼、送出／接受／拒絕邀請、公開個人頁與通話中加好友、`FRIEND_CODE_REQUIRED` 錯誤顯示、好友列表與邀請 model 移除他人 uid、新版格式 fixture。
- 不包含：解除好友、封鎖、羈絆展示（T-02）；聊天（T-03）。

**驗收條件**
- [x] 公開個人頁與通話中「加好友」都以 `{ friend_code }` 送出；通話中取 `session.peer_friend_code`（隨機配對）或來電／定向通話的好友碼。
- [x] 邀請列表的接受、拒絕打 `/api/friends/requests/{好友碼}/accept|decline`。
- [x] 以新版格式（不含他人 uid）的 fixture 跑好友列表、邀請列表的契約測試通過。
- [x] 任一好友相關請求收到 `400 FRIEND_CODE_REQUIRED` 時顯示後端 `message`。
- [ ] 實機在過渡期環境加好友、接受、拒絕都正常。

**實作設計**
- 前端：
  - `ApiConfig` 的好友路徑方法參數改為 `String friendCode`（一次改完，編譯器會列出所有呼叫點，T-02～T-05 依序處理各自的呼叫點；本卡只保證邀請相關呼叫點正確，其餘暫以既有 `friend_code` 欄位替換使其可編譯）。
  - `FriendService.sendRequest` 只收 `friendCode`；`acceptRequest`／`declineRequest` 改收好友碼。
  - `friend_model.dart` 移除他人 `uid` 欄位，以 `friendCode` 為識別（「暫時無法使用」的好友後端現在也會給 `friend_code`，型別改為非空）。
  - `friend_requests_screen.dart`、`public_profile_screen.dart`、通話中加好友的呼叫點改傳好友碼。
- 測試：依 `API/好友模組.md` 的回應範例建立新版格式 fixture（好友列表、邀請列表），補契約測試。

**依賴**：無


**進度**：實作完成（2026-09-29）；契約與服務測試通過，待實機驗證加好友、接受、拒絕。通話中加好友只在隨機配對顯示（好友通話的對方已是好友）。
