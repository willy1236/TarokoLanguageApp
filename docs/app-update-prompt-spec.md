# 版本更新提示 規格書

> 狀態：已定案（2026-09-27）　適用：TarokoLanguageApp（Android、iOS）

## 1. 目的

有新版本時，在使用者開啟 app 時提示更新，讓大家盡量使用最新版。**只提醒，不強制**——目前沒有需要擋住舊版的情境。

## 2. 範圍

| 做 | 不做 |
|---|---|
| Android、iOS 的更新提示 | Web、Windows |
| 可關閉的提醒 | 強制更新、擋住舊版 |
| 通用提示文字 | 顯示每版更新說明 |
| 導向商店／TestFlight | Play 應用程式內更新（背景下載） |
| — | 後端參與（全部在前端與 Firebase 設定） |

## 3. 已定案的前提

- 目前發布管道：Android 為 Google Play 封閉測試，iOS 為 TestFlight；之後轉正式上架。
- 可遠端調整的設定一律放在 Firebase Remote Config，不經後端。

## 4. 「最新版本」怎麼判定

同時參考兩個來源，**取兩者中較新的那個**：

1. **商店版本**：app 自行查詢 Play／App Store 上公開的版本。只看得到版本名稱（如 `1.0.1`），看不到 build number。測試期間通常查不到，正式上架後才會發揮作用。
2. **Remote Config 版本**：Android、iOS 各自一組，可填版本名稱加 build number（如 `1.0.1+8`）。

比較規則：先比版本名稱，名稱相同再比 build number。只有一邊查得到時就用那一邊；兩邊都查不到時視為沒有新版。

## 5. 使用者流程

1. 使用者冷啟動 app（從背景切回前景不檢查）。
2. app 一開就檢查，不等登入或條款同意流程。
3. 最新版本高於目前安裝的版本，且使用者沒有略過該版本 → 跳出提示，疊在最上層（就算底下是登入或條款同意畫面也照跳）。
4. 提示有三個按鈕：
   - **更新**：iOS 開啟 Remote Config 設定的連結（測試期為 TestFlight，上架後為 App Store）；Android 開啟 Play 商店的 app 頁面（連結同樣由 Remote Config 提供）。
   - **稍後**：關閉提示，下次冷啟動再問。
   - **略過此版本**：這一版不再提醒。
5. 關閉提示後回到原本的畫面，原流程不受影響。

## 6. 規則與例外

- 目前版本已是最新，或比查到的版本還新（例如開發中的版本）→ 不提示。
- 略過某一版之後又出更新的版本 → 照常提醒。
- 檢查失敗（沒網路、商店查不到、Remote Config 讀取失敗）→ 安靜略過，不提示、不顯示錯誤。
- 提示文字用通用說法，例如「有新版本可用，建議更新以獲得最佳體驗」。

## 7. 發版流程（維運規則）

- **測試期**：發版只加 build number。新版確實可以下載（Play 審核通過、TestFlight 處理完成）**之後**，才到 Remote Config 更新該平台的版本號。
- **正式上架後**：每次發版都要加版本名稱，商店比對才會自動生效；Remote Config 照樣可以用來補充或提早提醒。
- 兩個平台可以分開更新，例如 iOS 還在審核時先只改 Android。
- 正式上架時，把 iOS 的更新連結從 TestFlight 改成 App Store 頁面（只改 Remote Config，不用發新版）。

## 8. 驗收條件

- 用低於 Remote Config 版本的 build 冷啟動 → 出現提示；三個按鈕的行為符合第 5 節。
- 按「略過此版本」後重開 → 不提示；把 Remote Config 調到更新的版本後重開 → 再次提示。
- 按「稍後」後重開 → 再次提示。
- 目前版本等於或高於最新版本 → 不提示。
- 飛航模式下冷啟動 → 不提示、不出錯，app 正常使用。
- 首次安裝、停在條款同意或登入畫面時 → 提示疊在上層，關閉後可以繼續原流程。
- Web、Windows 執行時 → 完全不檢查。

## 9. 已接受的風險

- 測試期間商店比對無效，提醒完全依賴有沒有記得更新 Remote Config。
- 正式上架後，如果只加 build number、又沒更新 Remote Config，使用者就收不到提醒。
- 商店有快取，新版上架到 app 查得到之間可能有延遲。
- Remote Config 在 app 端有快取，改完之後不一定馬上生效。
